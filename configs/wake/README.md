# 호출어(KWS) 학습 설정

여기 있는 건 **학습 설정**이지 실행 설정이 아니다. 봇은 이 파일들을 읽지 않는다 —
런타임이 쓰는 건 ONNX 3종이고, 그 경로·임계값은
`configs/model_paths.yaml` 의 `wake:` 섹션에 있다.

`models/` 는 `.gitignore` 에 걸려 git 이 추적하지 않는다.
그 안에 학습 설정을 두면 **어떤 설정으로 만든 모델인지가 로컬 파일 하나에만 남는다.**
그래서 설정만 여기로 옮겼다(2026-08-05).

| 파일 | 용도 |
|---|---|
| `jaeha_v1.yaml` | `jaehabot.onnx` 를 만든 설정 (2026-08-02 학습). 현재 **롤백용**으로만 남김 |
| `jaeha_v2.yaml` | voxcpm 프롬프트 수정안 (**폐기 — 실행했으나 생성물이 불량이었다**) |
| `jaeha_v3.yaml` | `jaehabot_v3.onnx` 를 만든 설정 (2026-08-09 학습). **증강 오류로 폐기 → v4** |
| `jaeha_v4.yaml` | **배포 중인 `jaehabot_v4.onnx` 를 만든 설정** (2026-08-10 학습) |

⚠️ `tts_backend: voxcpm` 을 곧이곧대로 읽지 말 것 — v3·v4 음성은 전부 Supertonic 으로
만들었고 generate 는 배경음 폴더용으로만 돌렸다. 각 파일 머리말에 적어 뒀다.

⚠️ `jaeha_v4.yaml` 은 `model_name` 을 빼면 `jaeha_v3.yaml` 과 **완전히 같다.**
v3 → v4 의 차이는 설정이 아니라 **데이터 증강 방식**이다(아래 절).

젯슨 배치(2026-08-10): v4 는 `models/wake/v4/`, v3 는 `models/wake/v3/`,
v1 은 `models/wake/` 에 그대로.
**롤백 = `model_paths.yaml` 의 `model_dir`·`classifier` 두 줄 되돌리기.**
멜·임베딩 onnx 는 셋 다 바이트 동일(md5 대조) — 바뀐 건 분류기뿐이다:
v1 `dfe7b799` / v3 `06e7c727` / v4 `a649fe8d`.

학습은 노트북이 아니라 Colab 에서 돌린다(`livekit-wakeword` 가 py≥3.11 요구,
젯슨은 3.10). 노트북: `tools/colab_wake_train_v4.ipynb`(v4, 저장소에 있음),

결정 근거·운영 함정은 메모리 `wake-tool-decision` 참조.

## v3 → v4 에서 바뀐 것 (2026-08-10) — 증강 축 분리

v3 는 오프라인 recall 91% 로 통과하고도 **실기에서 빠르게 부르면 안 깨어났다.**
원인은 `--expand` 를 리샘플로 만든 것. 리샘플은 시간과 피치를 **같이** 바꾸므로
학습 데이터에서 '빠르다'와 '높다'가 항상 붙어 다녔고(격자의 대각선만 채운 꼴),
모델은 둘을 구분할 수 없어 **더 쉬운 피치를 골랐다.**

배포된 v3 에 같은 클립 120개를 짝지어 넣은 실측(thr 0.25):

| 변형 | 점수 중앙 | 임계초과 |
|---|---|---|
| 원본 | 0.798 | 98.3% |
| 리샘플(시간+피치) = v3 가 학습한 것 | 0.798 | 89.2% |
| **시간만**(사람이 빨리 말함) | **0.345** | **54.2%** |
| 피치만(아이 목소리) | 0.873 | 99.2% |

whisper 는 '시간만'도 92% 를 재하봇으로 전사한다 — **음성은 멀쩡하고 모델만 못 듣는다.**

고친 것:
- `time_stretch`(WSOLA, 피치 유지) + `pitch_shift`(길이 유지) 를 numpy 로 구현.
  두 축을 `EXPAND_GRID` 7칸으로 **따로** 곱한다. '빠르지만 낮은'(1.35, 1.0) 과
  '느리지만 높은'(1.0, 1.35) 이 둘 다 있어야 모델이 축을 분리해 배운다.
- TTS 재합성 없이 **정속 원본만 남기고 증강만 다시** 걸었다. 개수는 v3 와 동일
  (7276/1816/8000/2000) → 학습 시간이 같아 결과 차이를 증강 탓으로 좁힐 수 있다.
- 노트북에 **9-4 격자 칸별 재현율** 셀 추가. 전체 평균은 특정 조건의 실패를 숨긴다 —
  v3 가 정확히 그렇게 91% 로 통과했다.

**교훈: 증강 축이 서로 상관되면 모델은 그중 쉬운 축을 고른다.**
v3 때 클래스 대칭(긍정·부정에 같은 증강)은 챙겼지만 **축 독립성**을 놓쳤다.

## v2 → v3 에서 바뀐 것 (2026-08-09)

- **TTS 를 voxcpm → Supertonic 으로 교체.** v2 를 돌려 보니 voxcpm 이 만든 긍정 샘플이
  '재하봇'을 말하지 않았다(25초 폭주 포함). A/B 4변형 최고 통과율 40% → 손댈 노브가 없었다.
  Supertonic 은 검수 통과율 **91%**, 폭주 0건, 생성 4.5시간 → **22분**.
- **빠른 발화를 프롬프트가 아니라 신호처리로 만든다.** 합성 속도는 안전구간(0.85~1.05)만 쓰고,
  검수 통과본을 리샘플로 압축(1.15/1.25/1.35배)한다. 피치도 같이 올라가 유아 음역까지 덮인다.
  ⚠️ 부정 샘플에도 **같은 배속**을 걸었다 — 긍정에만 걸면 '빨라진 소리 = 호출어'를 배운다.
- 학습 하이퍼파라미터(steps·model_size·augment·batch_*)는 **v1/v2 그대로.**

## v1 → v2 에서 바뀐 것 (폐기된 안)

- `voice_design_prompts` 6 → 16개 (**빠름 7 / 보통 6 / 느림 3**).
  v1 은 한국어로 옮기면서 속도 묘사를 전부 빠뜨려 긍정 샘플이 죄다 보통~느린 속도였다.
  그래서 실기에서 "천천히는 되는데 빠르게 부르면 안 됨"이 났다.
  ⚠️ `length_scales` 는 Piper 전용 키라 voxcpm 백엔드에선 무시된다 — 속도는 **프롬프트 텍스트로만** 바꾼다.
- `target_phrases` 5 → 7개: 재하봇 / 제하봇 / 재하봇아 / 재하보사 / 재하부사 / 재하봇이 / 재하보시.
  호격 '~아'가 연음으로 [재하보사] 로 실현되는데 voxcpm 이 연음을 살린다는 보장이 없어 발음형을 병기했다.
- `n_samples` 2000 → 3000 (프롬프트가 늘어 프롬프트당 187개 확보). **생성 4~4.5시간.**
- 나머지(부정문구·steps·model_size·augment)는 v1 그대로 — 변수를 하나만 바꿔야 효과 판정이 된다.

## 성적

| | v1 (08-02) | v3 (08-09) | v4 (08-10) |
|---|---|---|---|
| AUT | 0.0302 | 0.0011 | — |
| Recall @ thr 0.50 | 40.1% | 91.1% (FPPH 0.09) | 89.8% (**FPPH 0.00**) |
| 배포 임계값 | 0.15 → 58.2% / FPPH 2.18 | 0.25 → 94.1% / 0.47 | **0.25 → 94.1% / 0.47** |

🔴 **열을 직접 비교하면 안 된다 — 시험지가 다르다.** v1 의 평가셋은 voxcpm(재하봇이라
말하지 않던 그 음성)이고 v3·v4 는 Supertonic 이다. 게다가 평가셋이 학습셋과 **같은 화자·
같은 문구**로 만들어졌고 다른 건 시드뿐이라, 이 재현율은 "Supertonic 분포를 학습했다"는
뜻이지 실제 아이 목소리 재현율이 아니다. **최종 판정은 젯슨 실기**(천천히/보통/빠르게 각 10회).

### 🔴 평균이 아니라 격자로 봐야 한다

v3 가 평균 91% 로 통과하고 실기에서 실패한 게 바로 이 때문이다. v4 격자 (thr 0.25):

| 시간 \ 피치 | 1.0 | 1.15 | 1.35 |
|---|---|---|---|
| **1.0** | 93% | 95% | 92% |
| **1.15** | 90% | — | 87% |
| **1.25** | — | 82% (1.25) | — |
| **1.35** | **67%** | **65%** | — |

- ✅ **축 분리는 됐다.** 시간을 고정하고 피치만 바꾸면 편차 3%p — 피치가 더는 점수를
  좌우하지 않는다. v4 가 노린 것이 이것이고, 달성됐다.
- ⚠️ **시간축 자체는 아직 약하다.** 편차 26%p. 1.25 까지 버티다 1.35 에서 무너진다.
  빠른 발화는 v3 54% → v4 67% 로 **올랐을 뿐 해결이 아니다.**
- ➡️ 실기에서 빠르게 10회 중 5회 이하면 다음 수는 임계값이 아니라 **실음성 녹음**이다.
  데이터가 모자란 게 아니다(7칸을 고르게 뽑았다) — 합성음 배속과 진짜 빠른 말이 다른 것이다.
