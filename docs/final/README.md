## 제출 파일(docx) 만들기

markdown 이 원본이고 docx 는 만들어 내는 것이다. 손으로 고친 docx 는 다음 실행에서
지워지니, 고칠 일이 있으면 `.md` 를 고치고 다시 만든다. 산출물은 `docs/final/docx/`
에 나오며 저장소에는 넣지 않는다(`.gitignore`).

```
python tools/build_docs_docx.py          # markdown -> docx (A4, 맑은 고딕, 그림 포함)
powershell tools/update_docx_fields.ps1  # 목차·쪽번호 채우기. -Pdf 를 주면 PDF 도
```

`pandoc` 이 없으면 `pip install pypandoc_binary` 로 받은 뒤 그 파이썬으로 돌린다.
그림(SVG)을 PNG 로 굽는 데 크롬을, 목차 필드를 채우는 데 워드를 쓴다. 두 번째 단계를
건너뛰면 목차가 빈 채로 나간다.

서식(글꼴·용지·제목 크기·표 테두리)은 `tools/docx_reference.py` 한 곳에서 정한다.

## 발명신고 양식(HWP) 채우기

세종대 산학협력단 양식은 저장소 밖에 있다(`jaeha_bot_docs/docs/제출 보고서`). 원본은
읽기만 하고 `*_초안.hwp` 로 따로 낸다.

```
python tools/make_invention_hwp.py "<양식 폴더>" docs/final/figures/wake-two-stage.png
```

한글과 `pyhwpx` 가 필요하다. 채우는 내용은 `tools/invention_desc_content.py` 에 있고,
칸 주소는 구역(list) 번호로 잡되 쓰기 전에 그 칸의 문구를 확인한다 — 엉뚱한 칸에 쓰는
사고를 막는 장치다.

🔴 **한글을 강제 종료한 직후 다시 띄우면 `open()` 이 조용히 멈출 수 있다.** 몇 초 기다렸다
돌리면 된다. 보안 모듈 등록과는 관계없다(레지스트리 방식으로 이미 등록돼 있고,
regsvr32 대상이 아니다). 그래도 막히면 미리 받아 둔 HWPML 을 `--hwpml` 로 넘긴다.
자세한 함정은 스크립트 맨 위에 적어 두었다.

## 두 보고서를 나눈 이유

`report.md` 는 서술형이라 읽는 데 시간이 걸린다. 심사자가 먼저 보는 것은 **무엇을 했고
결과가 무엇인지**이므로, 그 층을 `결과보고서.md` 로 따로 두고 표 중심으로 짧게 썼다.
`report.md` 는 "이 숫자가 어디서 나왔나"를 물었을 때 펼치는 문서로 남긴다.

두 문서의 수치는 같은 원본(`reports/`)에서 나온다. 한쪽을 고치면 다른 쪽도 함께 본다.

## 서술 대상

보고서가 서술하는 것은 전면 API 전환 이전의 로컬 파이프라인이며, 그 상태를 태그로
고정해 두었다.

```
git checkout doc-baseline-2026-09-12
```

개발은 2026년 9월 9일 회의에서 전면 API로 방향이 전환되었다. 전환 이후의 코드가 이
문서의 서술 대상을 지우지 않도록, 본문이 인용하는 코드와 측정 도구는 `main`에 남긴다.

(이전 태그 `doc-baseline-2026-09`는 9월 11일 작업 — 노래 재생 기능과 호출어 검증
수정 — 을 포함하지 않는다. 본문이 그 두 항목을 서술하므로 태그를 다시 잡았다.)

## 아직 정해지지 않은 것

- **문서 형식.** 결과보고서 양식 / 논문 형식 / 자유 중 미정이다. `report.md`는 형식
  중립으로 작성하였으므로, 결정되면 해당 양식에 옮긴다. 표와 그림은 그대로 쓸 수 있다.
- **합격선.** 실기 시연 / 영상과 보고서 / 문서만 중 미정이다. 어느 쪽이어도 데모 녹화가
  필요하다.
- **특허 출원 여부.** 출원하는 경우 보고서 공개 전에 내는 것이 가장 단순하다(특허 문서
  6절). 세종대 경로로 낸다면 산학협력단 발명신고가 먼저이고, 그 초안은 위 표의 두 문서에
  있다. 신고서에서 교수님이 정하셔야 하는 칸이 다섯 개다(발명신고서 초안 맨 끝).
- **아동 음성의 처리 경로.** 기관 명의의 ZDR 신청과 로컬 처리 유지 중 선택이 필요하다
  (본문 7.4절).

## 09-12 2차 검토에서 보충한 것

초안을 제3자 관점으로 다시 읽고 빠진 것을 채웠다. 사실 오류 한 건을 포함한다.

- **안전 평가(3.9절) 신설.** 목표 셋 중 하나가 안전인데 측정이 없었다. 같은 안전 문항
  14개의 과거 로그를 현재 판정기로 다시 채점해 표를 만들었다(위험 응답 15/28 → 0/42).
- **사실 오류 정정.** 초안 2.4절은 "응답 텍스트를 금지 낱말 규칙으로 검사한다"고 적었으나,
  `app/safety.py`와 `app/claims.py`는 평가 전용이고 운영 경로에 연결되어 있지 않다.
  2.5절에서 실제 구성을 다시 서술하고 6.3절 한계에 기재하였다.
- **구현 범위 표(2.3절) 신설.** 비전과 부모 브리핑은 스텁이고 놀이는 5종 중 2종만 동작한다.
  코드를 열어 보는 사람이 먼저 발견할 사실이므로 문서가 먼저 밝히는 편이 낫다.
- **대상 아동 실사용 미수행을 명시(6.3절).** 모든 실기 수치는 성인 발화로 얻었다.
- 놀이 내용(2.4절), 목소리 블라인드 선정(3.10절), 선행 인식의 41% 상한(4.8절),
  목표 대비 결과 표(8.1절), 남은 과제(8.3절), 실행 방법(부록 A.1), 참고 자료(부록 C)를
  추가하였다.

## 수치를 고칠 때의 규칙

본문의 모든 수치는 `reports/` 원본과 대조한 값이다. 새 수치를 넣거나 고칠 때는 원본
파일을 근거로 삼고, 부록 B의 대응표에 출처를 추가한다. 이 프로젝트는 측정 도구의 결함으로
결론이 뒤집힌 사례가 네 건 있었고(본문 4.8절), 모두 원본으로 돌아가 확인하는 과정에서
발견하였다.
