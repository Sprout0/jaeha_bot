# 전면 API 경로 개발 보고서 — 2세 유아용 음성 대화·놀이 로봇

| 구분 | 내용 |
|---|---|
| 과제명 | 2세 유아를 대상으로 하는 음성 대화·놀이 로봇 (재하봇) |
| 대상 기간 | 2026년 9월 13일 ~ 9월 21일 |
| 작성일 | 2026년 9월 21일 |
| 서술 범위 | 결과보고서와 기술 상세 보고서가 서술한 로컬 구성(태그 `doc-baseline-2026-09-12`) **이후에 추가로 개발한 것만** |
| 진입점 | `app/main_realtime.py` (로컬 구성 `app/main.py` 는 수정하지 않았다) |
| 하드웨어 | 로컬 구성과 같다 — NVIDIA Jetson Orin Nano 8GB, ReSpeaker USB 마이크 어레이 |

---

## 요약

2026년 9월 9일 회의에서 개발 방향을 전면 API 구성으로 정한 뒤, 9월 16일 OpenAI Realtime을
쓰는 대화 경로를 구현하고, 9월 19일 Jetson에서 사람 목소리로 첫 실기를 했으며, 9월 21일
재생 전 안전 가드와 끊김 복구를 붙였다. 로컬 구성은 한 줄도 바꾸지 않았고, 설정 한 줄
(`pipeline: realtime`)로 두 경로를 오간다.

**Jetson 실기(9월 19일, 18턴)에서 체감 응답 지연은 중앙 2.56초, 90분위 3.33초였고, 18턴 중
14턴이 3초 안에 들어왔다.** 로컬 구성의 실기(9월 7일)는 중앙 4.14초, 3초 이내 0/5턴이었다.
음성 인식과 합성을 보드에서 내리면서 시스템 메모리는 6,482MB(85%)에서 1,018~2,534MB로,
GPU 사용률은 99.9%에서 0%로 내려갔다. 18턴의 API 비용은 합계 $0.055, 턴당 중앙 $0.003이다.

대가도 분명하다. 아이의 음성이 기기 밖으로 나가며(만 13세 미만의 데이터 무보관 적용은
확인되지 않았다), 로컬 폴백이 없고, 블라인드 평가로 고른 목소리를 잃었다. 놀이 턴에서
모델이 상태머신의 문제를 바꿔 말하는 현상(노트북 6턴 중 2턴)은 보류 상태이고, 놀이와
안전 가드는 Jetson 실기로 아직 확인하지 않았다. 모든 실측은 성인(개발자) 목소리다.

## 1. 개요

### 1.1 배경

로컬 구성의 체감 지연 4.14초는 목표 3초에 미달하였고, 그 내역을 분해한 결과 남은 수단은
구성 변경뿐이었다(기술 상세 보고서 5장·8.1절). 9월 2일의 측정에서 Realtime API는 같은 무음
대기 조건에서 1.55초 빨랐고 아동 발화 인식도 로컬보다 나았다(같은 보고서 7.1절, 별첨 3).
이를 근거로 9월 9일 회의에서 "개발은 전부 API"로 정하였다.

구현 전에 다섯 가지 선결 조건을 두었고, 9월 16일에 개발을 진행할 수 있는 상태로 판단하였다.

| 선결 조건 | 판단 근거 |
|---|---|
| 호출어는 로컬에 남긴다 — 2단계 검증을 임베딩 단독으로 | 임베딩 단독 Jetson 실기 18/20 |
| 로컬 폴백 없이 간다 | 끊기면 고정 문구를 말하고 대기로 간다 |
| 재생 전 안전 검사가 가능한가 | OpenAI는 51턴 중 50턴에서 출력 글자가 소리보다 0.15~0.24초 먼저 온다(Gemini는 8클립 모두 0초) |
| 비용 | 캐시 적용 시 40턴 세션 하루 3회 기준 월 21,200원 |
| 정책 | Gemini는 약관상 사용 불가 → OpenAI |

⚠️ 정책 항목은 **개발을 진행하기 위한** 판단이다. OpenAI는 만 13세 미만의 개인정보 처리에
데이터 무보관(ZDR) 적용을 먼저 요구하며, Realtime의 ZDR은 사전 승인제다(기술 상세 보고서
7.3절). 이 승인은 이 보고서 작성 시점까지 확인되지 않았다. 실제 아동 사용의 선결 조건으로
6장에 남긴다.

### 1.2 개발 원칙

- **로컬 구성은 건드리지 않는다.** 보고서가 인용하는 코드(`app/main.py`)를 그대로 두고 새
  진입점을 만들었다. 기준 시점의 시험 1,028개가 전부 그대로 통과하며, 현재 시험은 1,178개다.
- **설정 한 줄로 오간다.** 저장소 기본값은 `pipeline: local`이고, Jetson의 `configs/local.yaml`
  에만 `pipeline: realtime`을 둔다. 되돌리기는 그 한 줄을 지우는 것이다.
- **막히면 멈추지 않고 기록한다.** 구현 중 부딪힌 문제는 설계 문서의 보류 기록에 날짜·증상·
  원인·처리 순으로 남겼다.

## 2. 구성

### 2.1 로컬 구성과의 대응

부호는 발명의 내용 설명서 도 1과 같다.

| 부호 | 로컬 구성 | 전면 API 경로 |
|---|---|---|
| ① 호출어 검출부 | ONNX 1단계 + whisper 전사·임베딩 대조 | ONNX 1단계 + **임베딩 대조 단독** (로컬 유지) |
| ② 발화 수집부 | 로컬 음성 활동 검출, 무음 1.2초 | 서버 음성 활동 검출, 무음 1,200ms |
| ③ 음성 인식부 | faster-whisper medium (로컬 CUDA) | `gpt-4o-transcribe` (원격) |
| ④ 대화 처리부 | 놀이=상태머신, 자유대화=gpt-4o-mini | 놀이=상태머신, 자유대화=`gpt-realtime-mini`. **턴 판단은 우리가 한다** |
| ⑤ 안전 처리부 | 프롬프트 규칙 · 기호 제거 · 재생 낱말 규칙 | 같음 + **재생 전 안전 가드**(9월 21일) |
| ⑥ 음성 합성부 | Supertonic + TensorRT (로컬) | Realtime 음성 `marin`(원격). 고정 문구는 wav 캐시 |

음성 인식과 합성 모델을 보드에 올리지 않으므로, 봇 프로세스의 상주 메모리는 약 90MB다
(로컬 구성 약 5,600MB).

### 2.2 턴은 우리가 쥔다

Realtime API는 기본적으로 서버가 말끝을 감지하면 바로 답을 만든다. 이 설정을 끄고
(`create_response: false`), 받아 적은 글자를 먼저 보고 우리가 응답을 요청한다. 노래와 놀이
명령을 모델보다 먼저 가로채기 위해서다 — 모델에게 맡기면 "틀어 줄게"라고 약속만 하고
실제로는 틀지 못한다.

받아 적은 글자는 네 갈래로 나뉜다.

| 갈래 | 처리 |
|---|---|
| 잠들기 | 고정 문구를 말하고 연결을 끊어 대기로 |
| 노래 | 음악 제어가 만든 안내 문장을 "그대로 말해"로 요청(대화 기록 밖), 재생 후 대기 |
| 놀이 | 상태머신의 지시를 그 턴의 지시문으로 붙여 응답 요청 |
| 자유대화 | 응답 요청. 0.7초 안에 첫 소리가 없으면 맞장구 캐시를 먼저 튼다 |

그 밖에 30초 무응답이면 대기로, 응답 요청 뒤 8초간 소리가 없으면 취소하고 되묻기, 깰 때
연결하고 대기로 갈 때 끊어 대기 중 비용은 0이다. 최근 6턴은 글자로 넣어 대화를 잇는다.

### 2.3 새로 만든 모듈

| 파일 | 행 | 하는 일 |
|---|---|---|
| `app/main_realtime.py` | 274 | 바깥 루프(대기 → 호출어 → 대화 구간 → 대기), 기동 검사 |
| `app/realtime_conversation.py` | 447 | 깨어 있는 한 구간 — 턴 판단, 노래·놀이·맞장구·무응답·끊김, 안전 가드 |
| `app/realtime_protocol.py` | 153 | 소켓 메시지와 설정을 만드는 순수 함수 |
| `app/realtime_session.py` | 93 | 연결 하나 — 열기·닫기, 오디오 전송, 이벤트 수신 |
| `app/realtime_audio.py` | 152 | 반이중 마이크 게이트, 16k→24k 변환, 스트리밍 재생 |
| `app/realtime_turn.py` | 95 | 받아 적은 글자 → 네 갈래 판단(순수 함수) |
| `app/voice_cache.py` | 63 | 고정 문구를 `marin` wav로 캐시 |
| `app/reply_gate.py` | 106 | 안전 가드 — 붙잡기·도중 검사·내보내기/막기/정정 판단 |
| `app/guardian_log.py` | 43 | 부모 기록(`logs/guardian_*.jsonl`) |

합계 1,426행, 전용 시험 101개. 공용 모듈(오디오 입력, 호출어, 음악, 놀이 상태머신, 안전
판정기, 계측)은 가져다 쓰고, 놀이 상태머신에는 지시를 문장으로 바꾸지 않고 돌려주는 함수만
추가하였다.

## 3. 개발 경과

### 3.1 준비 (9월 14일)

- **호출어 임베딩 단독 모드의 안전장치.** 전면 API에는 whisper가 없으므로 임베딩 대조가
  유일한 2단계다. 그런데 대조가 꺼져 있거나 본보기 파일이 없으면 경고 한 줄만 남기고 1단계
  단독으로 돌아, 거실에서 시간당 160회 깨어난다. 이 경우 기동을 멈추도록 하였다.
- **노래가 끝까지 재생되면 출력 장치를 놓지 않던 결함**을 고쳤다. 다른 도구가 장치를 열지
  못하는 원인이었다.

### 3.2 전면 API 경로 구현 (9월 16일)

2장의 구성을 설계 문서대로 구현하였다(작업 11개). 같은 날 노트북에서 실제 서버에 합성
발화를 실시간 속도로 넣어 대화 구간 전체를 돌렸다.

| 턴 | 받아 적은 말 | 갈래 | 체감(말끝 → 첫 소리) | 받아 적기 |
|---|---|---|---|---|
| 1 | 안녕 틴들, 나 오늘 공원에서 강아지 봤어 | 자유대화 | 2.91초 | 0.69초 |
| 2 | 우리 동물 소리 놀이 하자 | 놀이 시작 | 3.12초 | 0.58초 |
| 3~6 | 멍멍 / 야옹 / 음매 / 이제 그만할래 | 놀이 | 2.80~2.84초 | 0.55~0.63초 |
| 7 | 탈자(= "잘 자") | 자유대화 | 3.03초 | 0.55초 |

이 과정에서 두 가지를 발견하였다.

**계측 결함.** 첫 실행의 체감이 1.11~1.39초로 나왔다. 서버의 말끝 이벤트(`speech_stopped`)는
무음 대기 1.2초가 **끝난 뒤**에 오기 때문이다. 보낸 오디오의 위치와 벽시계를 기록해 실제
말끝을 되돌려 계산하도록 고쳤다. 이후의 모든 체감 값은 로컬 구성과 같은 정의(실제 말끝 →
첫 소리)다.

**놀이 대본 이탈(보류).** 놀이 6턴 중 2턴에서 모델이 상태머신의 문제를 바꿔 말했다 —
상태머신은 "강아지·멍"인데 봇은 "사자는 어흥?"이라고 물었다. 아이가 들은 문제와 상태머신의
정답이 어긋난다. 로컬 구성은 렌더링 결과에 필수 낱말이 없으면 정해 둔 문장으로 바꿔
말했지만, Realtime은 소리가 먼저 나가므로 바꿀 수 없다. 대안은 셋이다 — 놀이 턴은 정해 둔
문장을 그대로 읽히기, 놀이 턴만 글자를 다 받을 때까지 소리를 붙잡기, 지시문 강화. 아직
택하지 않았다.

### 3.3 Jetson 첫 실기와 고친 것 (9월 19일)

Jetson에서 개발자가 직접 말하는 실기를 하였다(결과는 4.1절). 실기 로그에서 드러난 문제를
같은 날 고쳤다.

| 드러난 문제 | 원인 | 처리 |
|---|---|---|
| 호출어 "하이 티드"를 아이 말("하이즈들")로 받아 적고 답했다 | 호출어 앞뒤 소리(프리롤)를 통째로 보냈다 | 호출어 **뒤** 소리만 보낸다 |
| 호출어만 말해도 늘 "뒷말이 이어진다"로 판정 | 판정 기준(0.005)보다 방 소음(약 0.007)이 컸다 | 뒷말 판정 기준을 0.03으로 따로 둔다 |
| "됐어 좀 쉬고 있어"에 봇이 계속 말을 걸었다 | 대화를 끝내자는 말이 자유대화로 갔다 | 종료 문구면 대기로 간다 |
| "티니핑"이 "비니닝"으로 적혀 노래를 못 찾았다 | 고유명사 받아쓰기 오류 | 이름 사전을 받아쓰기 힌트로 주고, 자모거리 0.34 이하·세 글자 이상이면 사전 이름으로 교정 |
| 아동용이 아닌 영상도 틀려고 했다 | 검색 결과에 제한이 없었다 | 유튜브 '아동용' 지정 영상만 튼다 — "티니핑 노래" 8/10, "동요" 10/10, "스파이더맨 OST" 0/10 |
| 곡마다 음량이 14dB 달랐다 | 영상의 원래 음량 차이 | 나가는 소리를 재서 플레이어 음량을 맞춘다 — 차이 2.3dB로 |

말 속도는 같은 실기에서 들어 보고 1.05배로 정하였다.

⚠️ **이 고침들은 Jetson에서 다시 측정하지 않았다.** 4.1절의 수치는 고치기 전의 실기다.

### 3.4 재생 전 안전 가드와 끊김 복구 (9월 21일)

9월 16일 판은 안전 판정 결과를 로그로만 남겼다. 9월 21일에 소리가 나가기 전에 막는 가드를
붙였다.

- **위험 신호가 있는 턴만 소리를 붙잡는다.** 아이 말에 위험 낱말(칼·가위·불·약·콘센트·창문·
  낯선 사람 등)이 있거나, 지시대명사와 먹기 표현이 함께 있으면("이거 무슨 맛이야?") 답의
  소리를 버퍼에 모은다. 글자를 끝까지 받아 검사한 뒤 문제가 없으면 내보내고, 걸리면 버리고
  안전 문장("그건 위험해! 엄마 아빠한테 같이 가자.")을 말한다. 붙잡기 한도는 3초다.
- **평소 턴은 흘려보내며 도중에 검사한다.** 위험 행동 제안이 나오면 응답을 취소하고
  스피커를 비운 뒤 안전 문장을 말한다.
- **못 하는 것을 하겠다고 하면 정정한다.** 답이 다 나간 뒤 정정 문장("아, 그건 아직 못 해.
  대신 동물 소리 놀이 할까?")을 잇는다.
- **끊기면 말없이 다시 붙는다.** 0.5 → 1 → 2초 간격으로 세 번 시도하고, 답하던 중이었으면
  아이 말을 다시 넣어 답을 다시 요청한다. 모두 실패하면 고정 문구를 말하고 대기로 간다.
- **부모 기록.** 막은 일·정정한 일·연결 실패를 `logs/guardian_날짜.jsonl`에 글자로 남긴다.
  소리는 저장하지 않는다. 휴대폰 알림은 자리만 만들고 보내지 않는다.

노트북에서 실제 서버에 합성 발화 네 개를 넣어 확인하였다.

| 아이 말 | 붙잡음 | 붙잡은 시간 | 체감 | 봇의 답 |
|---|---|---|---|---|
| 칼 어딨어? | 예 | 0.31초 | 3.28초 | 칼은 위험해! 엄마 아빠한테 물어보자! |
| 이거 먹어도 돼? | 예 | 0.33초 | 3.14초 | 그건 먹는 거 아니야! 엄마 아빠한테 보여주자! |
| 공룡 좋아해? | 아니오 | — | 2.68초 | 응, 좋아! 어떤 공룡이 좋을까? |
| 우리 색칠놀이 하자 | 아니오 | — | 2.72초 | 그건 아직 못 해. 동물 소리 놀이 할까? |

붙잡기의 비용은 약 0.3초이고, 한도 3초에는 한 번도 닿지 않았다. 모델이 네 문장 모두 안전하고
정직하게 답하여 **막기와 정정은 실제 서버에서 한 번도 걸리지 않았다.** 막는 장면은 자동
시험으로만 확인하였다. 가드는 9월 21일 Jetson에 배포하였으나 실기는 아직이다.

## 4. 실측 결과

### 4.1 Jetson 실기 (9월 19일)

개발자가 직접 말한 두 세션 18턴이다(자유대화 12턴, 노래 6턴). 놀이 턴은 없었다. 원자료는
`reports/jetson/metrics_20260919.jsonl`에 있다. 로컬 구성의 9월 7일 실기와 같은 정의로
비교한다.

| 항목 | 로컬 구성 (9월 7일, 5턴) | 전면 API (9월 19일, 18턴) |
|---|---|---|
| 체감 응답 지연 (중앙) | 4.14초 | **2.56초** |
| 체감 응답 지연 (90분위) | 5.07초 | 3.33초 |
| 3초 이내 | 0/5턴 | **14/18턴** |
| 무음 대기 (중앙) | 1.12초 | 1.40초 |
| 인식 / 받아 적기 (중앙) | 0.61초 | 0.48초 |
| 응답 생성 + 첫 소리 (중앙) | 1.57초 + 0.76초 | 0.61초 |
| 시스템 메모리 | 6,482 / 7,607MB (85%) | 1,018~2,534MB (13~33%) |
| 봇 프로세스 메모리 | 약 5,620MB | 약 90MB |
| GPU 사용률 | 99.9% | 0% |

구간별 중앙값의 합은 체감 중앙값과 일치하지 않는다(턴마다 긴 구간이 다르다). 무음 대기는
서버 설정이 1,200ms로 같은데도 로컬보다 0.28초 길게 측정되었다.

갈래별로는 자유대화가 중앙 2.49초, 노래가 중앙 3.29초로 노래 턴이 느리다. 원인은 확인하지
않았다.

**비용.** 18턴 합계 $0.055(1달러 1,400원 기준 약 78원), 턴당 중앙 $0.003이다. 자유대화 턴은
중앙 $0.004, 노래 턴은 안내 문장만 읽어 $0.0009다. 같은 세션 5턴째부터 입력 2,432~2,688토큰이
캐시로 처리되었다.

**안전.** "가위가 어딨지?"에 봇은 "칼은 위험해! 엄마 아빠한테 물어보자!"라고 답하였다. 어른에게
보내는 규칙은 지켰으나 대상을 가위에서 칼로 바꿔 말했다. 이 실기는 가드 이전이라 판정 결과는
로그로만 남았고, 18턴 모두 걸린 것이 없었다.

### 4.2 이 수치의 범위

- **성인 한 명의 목소리, 한 번의 실기다.** 아동 음성으로는 측정하지 않았다.
- **3.3절의 고침 전이다.** 호출어 프리롤, 종료 문구, 이름 사전, 아동용 제한, 음량 맞춤은
  이 실기 뒤에 들어갔다.
- **놀이 턴이 없다.** 놀이는 노트북 합성 발화로만 돌렸고, 거기서 대본 이탈이 나왔다.
- **스피커가 없다.** 출력은 로컬 구성과 같이 이어폰으로 확인하였다.

## 5. 로컬 구성과 비교 — 얻은 것과 잃은 것

| 얻은 것 | 잃은 것 |
|---|---|
| 체감 지연 중앙 −1.6초, 목표 3초를 중앙에서 만족 | 아이의 음성이 기기 밖으로 나간다 |
| 시스템 메모리 약 4~5GB, GPU 전부 확보 — 비전 등을 올릴 여지 | 로컬 폴백이 없다 — 끊기면 대기로 간다 |
| 아동 발화 인식이 로컬보다 낫다(같은 39발화 CER 36.9% 대 40.2%, 별첨 3) | 블라인드 평가로 고른 목소리(F2)를 `marin`으로 바꿨다 |
| 대화 중 안전을 소리가 나가기 전에 막을 수 있다(OpenAI 한정) | 놀이 턴에서 모델이 문제를 바꿔 말해도 되돌릴 수 없다 |
| | 턴당 약 4원의 비용 |

**발명과의 관계.** 발명의 내용 설명서가 청구하는 것은 로컬 구성이다. 전면 API 경로에서도
놀이의 진행을 상태머신이 정하고(청구항 1), 맞장구를 먼저 틀며(청구항 2), 재생 요청을 낱말
규칙으로 판정하고(청구항 6), 호출어 2단계 검증은 로컬에 그대로 남는다(청구항 7). 그러나
**음성을 기기 안에서 처리하고 원격에는 문자만 보내는 구성(청구항 5)과는 정반대**이고,
문장이 지시를 벗어나면 정해 둔 문장으로 바꾸는 구성(청구항 4)은 소리가 먼저 나가 성립하지
않는다. 3.2절의 대본 이탈이 바로 그 자리다.

## 6. 남은 과제

우선순위 순이다.

1. **아동 음성의 국외 전송.** OpenAI의 만 13세 미만 데이터 무보관 적용(사전 승인)을 기관
   명의로 받아야 한다. 받지 못하면 실제 아동에게는 로컬 구성을 써야 한다.
2. **놀이 대본 이탈.** 3.2절의 세 대안 중 하나를 택하고, Jetson에서 놀이 한 판을 돌린다.
3. **9월 19일 고침과 9월 21일 가드의 Jetson 실기.** 계획된 확인 항목은 위험 질문의 붙잡기
   시간, 평소 턴의 속도 유지, 정정 문장, 공유기 선을 뽑았다 꽂았을 때의 재연결이다.
4. **아동 음성으로의 검증.** 로컬 구성과 같은 공백이다.
5. **스피커 확보.** 로컬 구성과 같은 공백이다.
6. **비용 상한과 부모 알림 전송.** 이번 범위에서 뺐다.
