## 3. 발명의 상세한 설명

### 3.1 발명이 속하는 기술분야 및 가장 관련있는 논문 또는 특허 / 기술문서

상시 대기 상태의 음성 인터페이스에서 호출어(wake word)를 검출하는 장치 및 방법에 관한
것이다. 특히 저전력 임베디드 환경에서 제1 단계 경량 분류기와 제2 단계 검증기를 결합한
호출어 검출 구조에 관한 것이다.

**가장 관련있는 특허문헌**

| 구분 | 문헌 | 출원인 · 출원일 | 요지 |
|---|---|---|---|
| 특허문헌 1 | KR 10-2024-0045171 A | 주식회사 케이티, 2024. 4. 3. | 제1 신경망이 호출어의 시작을 식별하면 둘 이상의 시계열 구간을 기초로 제2 신경망을 병렬 구동하고 두 결과를 함께 고려하여 판단 |
| 특허문헌 2 | KR 10-2022-0064979 A | 주식회사 카카오엔터프라이즈, 2022. 5. 26. | 단말이 1차 검출, 임계치 초과 시 서버가 2차 검출하여 결과 회신 |
| 특허문헌 3 | KR 10-2018-0055968 A | 주식회사 인텔로이드, 2018. 5. 16. | 제1 인식 결과와 서버의 제2 인식 결과를 결합하여 판단 |
| 특허문헌 4 | KR 10-2017-0035231 A | 한국전자통신연구원, 2017. 3. 21. | 학습 시점에 제1 신경망의 출력을 입력으로 갖는 제2 신경망을 구성하여 훈련하는 **신경망 구축 방법** (IPC G06N3/04, 소멸) |
| 특허문헌 5 | US 9,275,637 B1 | Amazon Technologies, Inc. | 호출어 후보 문구의 선정 |

특허문헌 1이 본 발명과 가장 가깝다. 후보 판정 후 더 넓은 시간 창으로 제2 단계를 구동하고
결과를 결합한다는 골격이 사실상 같다. 다만 **검증을 언제 개시하는지**와 **제2 단계를
무엇으로 판정하는지**에 관한 한정은 두고 있지 않은 것으로 파악된다(4항 및 아래 3.4 참조).

특허문헌 4는 1차 조사에서 본 발명과 같은 층위의 문헌으로 인용하였으나, 원문 확인 결과
**학습 단계에서 두 신경망을 직렬로 쌓아 훈련하는 방법**이어서 층위가 다르다. 런타임에
후보를 판정한 뒤 별도의 검증 구간을 잡아 본보기와 대조하는 본 발명과는 대상이 다르다.
분류가 음성 인식(G10L)이 아니라 신경망 구조(G06N3/04)인 점도 이를 뒷받침한다.

**조사 범위와 한계.** 2026년 9월 11일 예비 조사, 9월 14일 국내 문헌 직접 확인을 수행하였다.
KIPRIS에서 `TL=[호출어]` 전수 12건, `CL=[호출어*임베딩]` 1건, `CL=[호출어*(유사도+코사인)]`
14건을 검토하였다. 서지사항과 초록까지 확인하였으며, **청구항 원문은 확인하지 못하였다**
(상세보기가 열리지 않았다). 해외 문헌은 예비 검토 수준이다. 정식 선행기술조사가 필요하다.

### 3.2 그 분야 종래기술의 설명 및 문제점

**(1) 제1 단계 단독 판정은 실사용 환경의 오검출을 감당하지 못한다.**

경량 분류기 단독으로 호출어를 판정하면 오검출이 과도하다. 본 발명의 실측에서 제1 단계
분류기는 실제 거실 녹음에 대해 **시간당 160회**의 후보를 올렸고, 이는 사전에 오프라인
표본으로 추정한 값의 **23배**였다. 따라서 제1 단계는 재현율을 우선하여 임계값을 열어 두고,
오검출 억제는 후단 검증이 담당하는 2단계 구조가 요구된다.

**(2) 제2 단계로 음성 인식 전사를 쓰는 종래 구성에는 두 가지 문제가 있다.**

첫째, **음성 인식기가 짧고 불확실한 음성에 대해 학습 데이터의 상용구를 생성한다.** 본
발명의 실험에서 성인이 호출어를 정확히 발성한 녹음에 대해 음성 인식기가 전혀 다른 문구를
출력하는 현상을 확인하였고, 해당 음성 파일을 증거로 보유한다. 출력 문자열이 입력 음성과
무관하므로 문자열 유사도의 판정 임계값을 어떻게 조정해도 해결되지 않는다.

둘째, **음성 인식기 호출의 지연이 크다.** 본 발명의 측정에서 제2 단계 검증 1회에 **0.78초**가
소요되었다. 상시 대기 구조에서 이 지연은 검증 중 입력 오디오의 누락과 후속 발화의 손실을
유발한다.

대안으로 화자 임베딩 대조를 제2 단계에 사용하는 구성을 고려할 수 있으나, 그 경우 통상
**별도의 임베딩 모델을 적재**해야 하므로 메모리가 제한된 임베디드 환경에서 비용이 발생한다.

**(3) 검증 구간의 개시 시점이 다루어지지 않는다.**

제2 단계 검증을 제1 단계가 후보를 판정한 시점에 즉시 개시하면 검증 정확도가 떨어진다.
본 발명의 측정에서 제1 단계 분류기 점수의 최고점은 후보 판정 시점보다 **0.3~0.5초 뒤**에
나타났다. 즉 후보 판정 시점의 오디오 구간은 호출어 발성의 전체를 포함하지 않는다.
종래 문헌은 후보 판정 시점에 즉시 제2 단계를 구동하거나, 개시 시점에 관한 한정을 두지
않는다.

**(4) 검증 구간이 짧으면 무증상 고장이 발생한다.**

검증 구간의 길이가 대조 연산이 요구하는 최소 길이에 미달하면, 검증기는 오류를 반환하지
않고 **유사도 0을 반환하여 항상 불합격**을 내는 상태가 된다. 오류가 나지 않으므로 고장이
드러나지 않는다. 본 발명은 검증 구간 2.0초 설정에서 이 상태를 실제로 겪었으며, 이 조건은
종래 문헌에서 명시적으로 다루어지지 않는다.

### 3.3 발명이 이루고자 하는 기술적 과제

1. 제2 단계 검증을 위한 **추가 메모리 점유를 0으로** 하면서 음성 인식 전사에 의존하지 않는
   검증 수단을 제공한다.
2. 검증 구간의 **개시 시점을 제1 단계 점수의 거동에 근거하여 결정**하여, 같은 모델과 같은
   임계값에서 호출 검출률을 높인다.
3. 검증 구간의 **길이를 대조 연산의 요구 조건으로부터 결정**하여, 유사도가 항상 0이 되는
   무증상 고장을 구조적으로 방지한다.
4. 제2 단계 검증의 **소요 시간을 단축**하여 상시 대기 구조에서 입력 오디오의 누락을 줄인다.

### 3.4 발명의 구성 및 작용

#### 3.4.1 전체 구성

제1 검출기는 멜 스펙트로그램 프론트엔드, 임베딩 추출기, 분류기를 직렬로 포함한다. 입력
오디오를 80ms 프레임 단위로 처리하며, 분류기의 출력 점수(110)가 임계값 0.05를 처음 넘는
시점을 호출어 후보 판정 시점(120)으로 한다.

호출어 후보가 판정되면 다음 세 조건을 결합하여 제2 단계 검증을 수행한다.

**(가) 제1 단계가 이미 적재한 임베딩 추출기를 제2 단계가 재사용한다.**

제2 단계 검증은 새로운 모델을 적재하지 않고, 제1 단계가 이미 메모리에 올려 둔 임베딩
추출기의 출력을 그대로 사용하여 미리 등록된 본보기 임베딩(170)과 코사인 유사도를 산출한다.
이로써 제2 단계 검증의 추가 메모리 점유가 0이 된다.

**(나) 검증 구간을 후보 판정 시점으로부터 소정 시간 지연시켜 개시한다.**

제1 단계 점수의 최고점(130)이 후보 판정 시점(120)보다 뒤에 나타나는 특성을 이용한다.
후보 판정 후 소정의 대기 시간(140)이 경과한 시점부터 검증 구간(150)을 취한다. 일 실시예에서
대기 시간은 **0.48초**이다.

**(다) 검증 구간의 길이를 대조 연산이 요구하는 임베딩 개수의 하한으로부터 결정한다.**

임베딩 추출기는 첫 임베딩을 생성하는 데 16프레임(멜 76행)을 소비하므로, 요구 개수 16개를
채우려면 31프레임, 즉 **2.48초**가 필요하다. 일 실시예에서는 여유를 두어 검증 구간을
**3.0초(38프레임)** 로 설정하며, 이때 임베딩 열(160)은 18개가 된다. 미달 시 유사도가 항상
0이 되는 무증상 고장을 구조적으로 방지한다.

검증 구간(150)의 오디오를 제1 검출기의 임베딩 추출기에 입력하여 96차원 임베딩 열(160)을
얻고, 미리 등록된 본보기 임베딩(170)과의 코사인 유사도를 산출한다. 유사도가 임계값(일
실시예에서 0.85 또는 0.88)을 넘으면 호출을 확정(180)한다.

**(라) 추가 구성 — 전사 판정과의 논리합.**

임베딩 대조와 음성 인식 전사에 의한 문자 유사도 판정(190)을 논리합(OR)으로 결합한다.
음성 인식기가 상용구를 생성하여 전사 판정이 실패하는 경우에도 임베딩 대조가 호출을
구제한다.

#### 3.4.3 실험예

**실험 방법.** NVIDIA Jetson Orin Nano 8GB 및 ReSpeaker USB 마이크 어레이로 구성된 실기
장치에서, 성인 화자가 호출어를 발성한 35건에 대해 동일 모델·동일 임계값 조건에서 검증
구간의 조건만 바꾸어 호출 검출 여부를 측정하였다. 헛깨움은 거실 환경 45분 연속 녹음에서
계수하였다. 홀드아웃 검증은 학습에 사용하지 않은 화자의 발화 15건으로 수행하였다.

**실험예 1 — 종래 구성(전사 판정 단독)과의 비교**

| 항목 | 전사 판정 단독 | 본 발명 |
|---|---|---|
| 제2 단계 검증 1회 소요 | 0.78초 | **0.08초** |
| 추가 메모리 점유 | 음성 인식 모델 상주 | **0** |
| 호출 검출 (실기 35건) | 23/35 | **25/35** |
| 헛깨움 (거실 45분) | 2회 (시간당 2.67회) | 1회 (시간당 1.33회) |
| 홀드아웃 검증 (15건) | 10/15 | **14/15** |

**실험예 2 — 구성 (나)와 (다)의 기여 분리**

같은 모델, 같은 임계값에서 검증 구간의 개시 시점과 길이만 바꾸었다.

| 검증 구간 조건 | 호출 검출 (35건) |
|---|---|
| 후보 직후 개시, 구간 2.0초 | **0/35** (유사도가 항상 0 — 무증상 고장) |
| 후보 직후 개시, 구간 3.0초 | 15/35 |
| **후보 후 0.48초 개시, 구간 3.0초** | **25/35** |

구간 길이만 확보하면 15/35가 되고(구성 (다)의 효과), 개시 시점을 지연시키면 25/35가 된다
(구성 (나)의 효과). 모델과 임계값은 전 조건에서 동일하다.

**실험예 3 — 대기 시간에 최적값이 존재함**

제1 단계를 통과한 호출 11건에 대해 대기 시간만 바꾸어 측정하였다.

| 후보 후 대기 시간 | 0.24초 | **0.48초** | 0.80초 | 1.04초 |
|---|---|---|---|---|
| 유사도 임계값 0.85 | 6/11 | **10/11** | 9/11 | 7/11 |
| 유사도 임계값 0.88 | 3/11 | **10/11** | 9/11 | 5/11 |

대기 시간을 더 늘리면 검출률이 다시 감소한다. 즉 '더 오래 기다린다'가 아니라 **'특정
지연에서 최적'** 이라는 형태의 효과이다. 본보기 임베딩이 발성의 최고점 구간에서 생성
되었기 때문이며, 이 점이 구성 (나)를 단순한 지연 추가와 구별한다. 두 임계값에서 최적점이
같게 나타나는 것도 이를 뒷받침한다.

#### 3.4.4 종래기술과의 차이점 요약

| 구분 | 본 발명 | 가장 가까운 문헌 (특허문헌 1, KT) |
|---|---|---|
| **(A) 검증 구간의 개시 시점** | 후보 판정 후 소정 지연 뒤 개시. 지연은 제1 단계 점수가 최고점에 도달하는 시간에 근거하며, **최적값이 존재**한다 | '시작이 식별되면' 즉시. 지연에 관한 한정이 없다 |
| **(B) 검증 구간의 길이** | 대조 연산이 요구하는 최소 임베딩 개수로부터 역산. 무증상 고장을 구조적으로 방지 | 한정 없음 |
| **(C) 제2 단계의 성격** | 인식이 아니라 등록 본보기와의 임베딩 코사인 유사도. 제1 단계가 이미 적재한 추출기를 재사용하여 추가 메모리 0 | 제2 **음성 인식 신경망** |

본 발명의 신규성은 (A)(B)(C)의 조합에 있다. 런타임 2단계 검증 구조 자체는 공지이다
(특허문헌 1~3).

## 4. 특허 청구범위

> 양식에 "반드시 작성하지 않아도 되며, 특허 받고자 하는 기술의 범위를 간략히 기재"로
> 적혀 있다. 아래는 방향 확인용 초안이며 그대로 출원할 것을 전제하지 않는다.

**청구항 1.** 상시 대기 상태에서 입력 오디오를 프레임 단위로 처리하여 호출어를 검출하는
방법으로서,

멜 스펙트로그램 프론트엔드와 임베딩 추출기 및 분류기를 포함하는 제1 검출기가 상기 입력
오디오로부터 호출어 후보를 판정하는 단계;

상기 후보의 판정 시점으로부터 소정의 대기 시간이 경과한 시점을 시작점으로 하는 검증
구간을 설정하는 단계 — 상기 대기 시간은 상기 분류기의 출력 점수가 최고점에 도달하는
지연에 근거하여 정해지고, 상기 검증 구간의 길이는 후술하는 유사도 산출이 요구하는 최소
임베딩 개수를 상기 검증 구간의 프레임 수가 만족하도록 결정된다;

상기 검증 구간의 오디오를, 상기 제1 검출기의 판정에 사용된 것과 동일한 인스턴스이며 상기
검증을 위하여 추가로 적재되지 않는 상기 임베딩 추출기에 입력하여 임베딩 열을 획득하는
단계; 및

상기 임베딩 열과 미리 등록된 본보기 임베딩의 유사도가 임계값을 넘는 경우 호출을 확정하는
단계를 포함하는 호출어 검출 방법.

**청구항 2.** 제1항에서, 상기 대기 시간은 상기 분류기의 출력 점수가 최고점에 도달하는
지연의 분포로부터 정해지되, 해당 지연보다 길게 설정된 경우 검출률이 감소하는 값으로
정해지는 호출어 검출 방법.

**청구항 3.** 제1항에서, 상기 검증 구간의 오디오에 대한 음성 인식 전사와 상기 호출어
문구의 문자 유사도 판정을 추가로 수행하고, 상기 임베딩 유사도 판정과 상기 문자 유사도
판정 중 어느 하나가 충족되면 호출을 확정하는 호출어 검출 방법.

**청구항 4.** 제1항의 방법을 수행하는 호출어 검출 장치.

**청구항 5.** 제1항의 방법을 컴퓨터에 실행시키기 위하여 기록매체에 저장된 컴퓨터 프로그램.
