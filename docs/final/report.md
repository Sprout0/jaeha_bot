## 요약

2세 유아가 음성만으로 상호작용하는 대화·놀이 로봇을 Jetson Orin Nano 단일 보드 위에
구현하였다. 호출어 검출부터 음성 합성까지 여섯 단계로 구성된 파이프라인이 보드 위에서
동작하며, 대규모 언어모델 호출만 원격 API를 사용하고 나머지는 모두 로컬에서 처리한다.
2026년 9월 7일 실기 시험에서 호출어 인식부터 응답 재생까지 전 구간이 5턴 연속으로
동작하는 것을 확인하였고, 이때 측정된 체감 응답 지연은 중앙값 4.14초, 90분위 5.07초였다.

이 프로젝트의 결과물은 동작하는 시스템 그 자체보다, **성인 음성을 전제로 만들어진 음성
처리 부품이 유아 음성에서 어느 정도로 무너지는지를 재현 가능한 실험으로 측정한 기록**에
있다. 문장 종료점 검출 모델은 같은 코드 경로에서 성인 음성(모델 제공사 공개 데이터) 97.8%의
재현율을 유아 음성에서 37.3%로 떨어뜨렸고, 음성 인식은 3~6세 발화에서 문자 오류율 31.46%를 넘지 못했다. 이 두
수치는 "아이 말을 정확히 알아듣는다"를 전제하는 설계가 성립하지 않음을 뜻하며, 보고서
전반의 설계 결정이 그 제약에서 출발한다.

안전에 대해서는 별도의 측정을 수행하였다. 동일한 안전 문항 14개에 대해 응답 로그를 현재
판정기로 다시 채점한 결과, 프롬프트에 안전 규칙이 없던 시점에는 위험 응답이 28회 중
15회였고 규칙 적용 후에는 42회 중 0회였다. 같은 문항을 세 모델에 물었을 때 모두 실패했다는
점에서, 원인은 모델 선택이 아니라 프롬프트 설계였다(3.9절).

측정 결과로 기각한 선택지를 별도의 장(4장)으로 분리하여 서술하였다. 도입을 검토했으나
측정값이 이득을 지지하지 않아 채택하지 않은 항목이 아홉 건이며, 그중 한 절은 측정 도구
자체의 결함을 먼저 발견하여 결론이 뒤집힌 네 사례를 모았다. 음의 결과를 방법과 함께 남기는
것이 이 보고서의 서술 원칙이다.

미검증 항목과 미구현 범위를 6장에 별도로 구획하였다. 계획에 포함되었으나 구현하지 못한
기능이 둘(비전, 부모 브리핑) 있고, 놀이는 5종 중 2종만 동작한다. 검증 측면의 가장 큰
공백은 스피커 미보유로 인한 음향 결합 계층이며, 재생 선행 여유값(`PLAY_PAD_S`)은 도입
이래 한 번도 측정되지 않았다. 호출어 검출기의 학습 데이터에 실제 아동 음성이 한 건도
포함되지 않았고, **대상 아동을 상대로 한 실사용 시험은 수행하지 않았다.**

## 1. 서론

### 1.1 배경과 목표

대상 사용자는 만 2세 유아다. 이 연령대는 문자를 읽지 못하고 화면 조작도 어려우므로,
상호작용 수단이 음성으로 제한된다. 동시에 발화 자체가 불완전하여 성인용 음성 인터페이스가
가정하는 조건 — 명확한 발음, 문장 단위의 완결된 발화, 일정한 발화 속도 — 이 거의 성립하지
않는다.

목표는 다음 세 가지로 설정하였다.

1. 아이가 이름을 불러 깨우고, 말을 걸면 답하는 대화 루프를 단일 보드에서 동작시킨다.
2. 응답 지연을 아이의 주의 지속 시간 안에 둔다. 초기 목표는 체감 3초 이내로 두었다.
3. 아동 대상 시스템에 요구되는 안전 조건 — 부적절한 응답 차단, 의도하지 않은 소리 재생
   방지 — 을 구조적으로 보장한다.

### 1.2 유아 음성이 왜 어려운가 — 세 가지 측정

프로젝트 초기에 "유아 음성 인식이 어렵다"는 통념을 문헌에서 확인한 뒤, 우리 조건에서
직접 재현하였다. 세 실험 모두 공개 데이터(AI-Hub 한국어 아동 음성)와 우리 코드 경로를
사용하였다.

**첫째, 음성 인식의 정확도가 구조적 한계에 부딪힌다.** faster-whisper 세 모델을 3~6세
발화 153건(화자 114명)에 대해 채점한 결과는 다음과 같다.

| 모델 | 인식 시간 중앙 | 90분위 | 문자 오류율 | 심각 실패(오류율 50% 초과) | 상주 메모리 |
|---|---|---|---|---|---|
| small | 0.557초 | 0.786초 | 41.08% | 56/153 | 859MB |
| medium | 1.190초 | 1.607초 | **31.46%** | 38/153 | 1,884MB |
| large-v3-turbo | 1.549초 | 1.686초 | 36.38% | 44/153 | 2,009MB |

최선의 모델에서도 세 글자 중 하나가 틀린다. 연령별로 보면 3세 44.3%, 4세 32.1%, 5세 28.1%,
6세 23.6%로 어릴수록 급격히 악화된다. 실제 대상인 2세는 이 구간의 바깥이며, 공개 데이터가
없어 측정하지 못하였다. 이 수치는 문헌의 5세 단어 오류율 21%와도 방향이 일치한다.

이 결과가 설계에 미친 영향은 결정적이다. 아이 발화의 원문을 정확히 받아 처리하는 구조는
성립할 수 없으므로, 놀이 상호작용은 아이의 발화 내용을 판정 근거로 쓰지 않고 카드에 미리
정의된 정답 낱말과의 대조로 처리하도록 설계하였다(3.7절).

**둘째, 발화가 끝났는지를 판정하는 모델이 유아에게서 무너진다.** 체감 응답 지연의 27%는
음성 활동 검출의 무음 대기 시간(1.2초)이다. 말이 끝난 것을 아는 방법이 "1.2초 동안 조용한지
세기"뿐이기 때문이다. 오디오만으로 발화 완결을 판정하는 Smart Turn v3.2를 도입하면 이
대기를 0.2초로 줄일 수 있다고 보아, 같은 코드 경로에서 벤더 데이터와 우리 데이터를 나란히
채점하였다.

| 표본 | 표본 수 | 재현율(무음 0.2초, 문턱 0.5) |
|---|---|---|
| 벤더 제공 한국어 성인 | 160 | 97.80% |
| AI-Hub 3~6세 | 153 | 37.25% |

60%p의 격차다. 음의 결과를 신뢰할 근거를 먼저 확보하기 위해, 벤더 데이터와 벤더 라벨로
우리 채점 도구를 먼저 검증하였다(정확도 99.38%, 재현율 100.00%, 오탐 1.45% — 벤더 공개치
96.96 / 98.40 / 2.25를 상회). 도구가 아니라 대상이 원인이라는 뜻이다. 상세는
`reports/turn/README.md`에 있다.

부산물로 아이 발화의 내부 쉼 분포를 얻었다. 153건 496구간에서 중앙 0.080초, 90분위
0.320초다. 아이는 문장 중간에 오래 쉬며, 그 쉼을 종료로 읽으면 말을 끊는다. 판정 모델
없이 고정 대기를 1.2초에서 0.9초로 줄이는 것만으로 0.30초를 얻을 수 있고 이때 말끊김은
2.0%에서 5.2%로 증가한다는 계산이 여기서 나온다.

**셋째, 호출어가 음성 인식기의 어휘 밖에 있으면 연쇄적으로 비용이 발생한다.** 초기 호출어
'재하봇'은 whisper의 어휘에 없는 조합이어서 힌트 없이는 한 번도 정확히 전사되지 않았다.
이 문제가 초기 프롬프트 주입, 2패스 검증, 검증 시간 증가, 실시간 처리 포화로 이어지는
사슬을 만들었다. 호출어를 교체하여 사슬의 첫 고리를 끊은 과정을 3.1절에 서술한다.

### 1.3 서술 대상과 검증 방법

개발은 2026년 9월 9일 회의에서 전면 API 구성으로 방향이 전환되었다. 이 보고서가 서술하는
대상은 전환 이전의 로컬 파이프라인이며, 해당 상태를 태그로 고정하였다.

```
git checkout doc-baseline-2026-09-12
```

보고서에 인용된 모든 수치는 `reports/` 하위의 원본 로그 및 JSON과 대조한 값이다. 이 원칙을
명시하는 이유는, 이 프로젝트에서 측정 도구의 결함으로 결론이 뒤집힌 사례가 네 건 있었기
때문이다(4.9절). 인용 수치 중 실측이 아닌 설계 계산치는 해당 위치에 그 사실을 표시하였다.

원자료가 큰 실험은 요약만 저장소에 남기고 원자료는 도구로 재생성하도록 하였다. 재현
실행 방법과 재현 절차는 부록 A에, 장별 근거 파일 대응은 부록 B에, 인용한 데이터·모델·
특허·법령은 부록 C에 정리하였다.

## 2. 시스템 구성

### 2.1 하드웨어

- NVIDIA Jetson Orin Nano 8GB. 시스템 메모리와 GPU 메모리를 공유하는 구조여서, 모델
  적재 전략이 성능이 아니라 동작 가능성을 좌우한다(5.4절).
- ReSpeaker USB 마이크 어레이. 입력 16kHz 단일 채널로 사용하며, 출력도 같은 장치의
  3.5mm 잭을 경유한다.
- 스피커는 확보하지 못하였다. 출력 계통의 검증은 이어폰으로 수행하였으며, 그로 인해
  미검증으로 남은 항목을 6.3절에 명시한다.

### 2.2 파이프라인

전체 구성과 구간별 실측 지연을 그림 1에 정리하였다.

![](figures/pipeline-block.svg)

*그림 1. 파이프라인 구성과 구간별 실측 지연*

입력에서 출력까지 여섯 단계를 거친다.

1. **호출어 검출.** ONNX 분류기(1단계)가 후보를 올리고, 2단계 검증기가 확정한다.
2. **발화 수집.** 음성 활동 검출이 무음 1.2초를 세어 발화의 끝을 판정한다.
3. **음성 인식.** faster-whisper medium을 로컬 CUDA에서 실행한다.
4. **응답 생성.** 원격 API(gpt-4o-mini)를 호출하고, 실패 시 로컬 GGUF 모델로 대체한다.
5. **안전 처리.** 응답의 이모지·기호를 코드에서 제거하고, 소리 재생 요청을 낱말 규칙으로
   판정한다. 응답 문자열의 위험 판정기는 평가 전용이며 이 경로에 연결되어 있지 않다(2.5절).
6. **음성 합성.** Supertonic을 TensorRT 엔진으로 실행한다.

재생 중에는 자기 목소리가 마이크로 되돌아오는 것을 `AudioSource.drain()`이 구조적으로
차단한다. 입력 버퍼를 비우는 방식이어서 별도의 음향 반향 제거를 요구하지 않는다.

### 2.3 소프트웨어 구성과 구현 범위

`app/` 아래 22개 모듈, 7,031행이다. 측정·데이터 생성 도구가 `tools/` 8,966행, 테스트가
`tests/` 11,847행으로, 운영 코드보다 검증 코드가 많다. 이는 하드웨어와 사람의 목소리가
필요한 시스템에서 되돌리기 쉬운 상태를 유지하려는 선택의 결과다.

계획된 기능과 실제 구현 상태를 구분하여 밝힌다.

| 기능 | 상태 | 비고 |
|---|---|---|
| 호출어 검출 | 구현 | ONNX 2단계. `wake.py`, `wake_onnx.py`, `wake_embed.py` |
| 음성 인식 | 구현 | `stt_module.py`. 에너지 기반 음성 활동 검출과 환각 가드 포함 |
| 응답 생성 | 구현 | `agent.py`. 원격 API 기본, 로컬 GGUF 폴백 |
| 음성 합성 | 구현 | `tts_module.py`. TensorRT 엔진 |
| 놀이 상태머신 | 부분 | `education_modes.py`. 5종 중 **2종만 동작**(2.4절) |
| 소리·노래 재생 | 구현 | `music.py`, `youtube.py`. 기본 꺼짐, Jetson에서만 활성 |
| 안전·날조 판정기 | 평가 전용 | `safety.py`, `claims.py`. **런타임 경로에 연결되지 않았다**(2.5절) |
| 비전 | 미구현 | `vision_module.py`는 스텁. 인스턴스만 생성되고 호출되지 않는다 |
| 부모 브리핑 | 미구현 | `daily_briefing.py`는 스텁. 참조하는 코드가 없다 |

비전과 부모 브리핑은 과제 계획에 포함되어 있었으나 구현하지 못하였다. 두 모듈을 스텁으로
남긴 이유는 자리를 표시하기 위한 것이며, 파일에 미구현임을 명시하여 "구현되었으나 쓰지
않는 코드"로 오해되지 않도록 하였다. 비전을 붙이지 못한 직접적인 제약은 메모리다 — 음성
합성의 TensorRT 엔진이 이미 2,887MB를 점유하고 있어(5.4절) 객체 검출 모델을 함께 올릴
여유가 없다.

### 2.4 놀이와 자유대화의 분기

음성 인식 결과는 놀이 턴과 자유대화 턴으로 갈린다.

놀이 턴은 결정론적 상태머신이 처리한다. 흐름, 정답 판정, 종료 조건은 코드가 정하고, 언어
모델은 칭찬과 질문의 **문장만** 렌더링한다. 렌더링이 실패하거나 지시를 벗어나면 템플릿으로
대체되어 놀이가 멈추지 않는다. 놀이의 내용은 코드가 아니라 `scenarios/scenario_cards.json`
에서 읽으므로, 카드를 편집하여 내용을 바꿀 수 있다.

| 놀이 | 상태 | 내용 |
|---|---|---|
| 동물 소리 흉내 | 동작 | 카드 8종(멍멍·야옹·음메·꿀꿀·꽥꽥·삐약삐약·개굴개굴·매애) |
| 따라 말하기 | 동작 | 같은 뼈대, 항목만 다르다 |
| 색칠 놀이 | 카드만 | 상태머신 미구현 |
| 사물 찾기 | 카드만 | 비전 의존 |
| 감정 대화 | 카드만 | 상태머신 미구현 |

판정을 흉내와 따라 말하기 방향으로 설계한 것은 1.2절의 문자 오류율 31.46%에 대한 직접적인
대응이다. 아이가 무엇이라도 말하면 성공으로 처리하고, 소리가 대략 맞으면(자모 유사도)
추가 반응을 준다. 정답 낱말을 정확히 인식할 필요가 없는 구조다.

자유대화 턴은 언어모델을 호출한다. 이 경로에만 맞장구를 삽입하며, 놀이 턴에서는 응답이
이미 결정되어 있어 대기가 발생하지 않으므로 삽입하지 않는다.

### 2.5 안전 계층의 실제 구성

운영 경로에서 동작하는 안전 장치는 다음 네 가지다.

1. 시스템 프롬프트의 안전 규칙. 위험한 소재가 나오면 어른에게 보내도록 지시한다.
2. 응답 후처리. 이모지와 기호를 코드에서 제거한다. 프롬프트로도 금지하지만 모델이 지키지
   않을 수 있으므로 코드에서 다시 제거한다.
3. 소리 재생 요청의 낱말 규칙 판정(3.7절).
4. 음성 인식의 환각 가드.

한편 `app/safety.py`와 `app/claims.py`는 **평가 지표로만 사용되며 운영 경로에 연결되어
있지 않다.** 두 모듈은 `tools/eval_llm.py`와 테스트에서만 임포트된다. 응답을 내보내기 전에
검사하여 걸리면 대체 응답을 내는 런타임 가드는 설계는 되어 있으나 적용하지 않았다. 이
사실을 6.3절의 한계에 기재한다.

안전 확보의 실제 수단이 왜 판정기가 아니라 프롬프트가 되었는지는 3.9절에 측정과 함께
서술한다.

### 2.6 소리와 노래 재생

효과음과 동요는 로컬 파일 재생을 기본으로 한다. 음악 스트리밍 서비스의 API 경로가 약관상
전부 닫혀 있음을 확인한 결과다(4.7절). 이후 유튜브 공식 IFrame Player API를 통한 임베드
재생이 허용 경로임을 확인하여 보조 경로로 추가하였다. 로컬 음원을 우선 탐색하고, 없을 때만
유튜브를 사용한다. 기본값은 꺼짐이며 Jetson에서만 활성화한다.

ReSpeaker 출력 장치는 단일 프로세스만 점유할 수 있어, 브라우저가 장치를 쥐면 봇이 말을
하지 못한다. ALSA `dmix` 기반 공유 장치를 별도로 정의하여 해결하였고, 이때 추가되는 지연은
4ms였다(하드웨어 직결 96ms 대 공유 장치 100ms).

## 3. 설계 결정과 근거

각 항목을 결정, 검토한 대안, 채택 근거의 순서로 서술한다. 이 장의 모든 수치는 측정값이며,
실측이 아닌 항목은 그 사실을 명시하였다.

### 3.1 호출어를 '재하봇'에서 '하이 티드'로 교체

12화자 × 3가지 발화 속도로 합성한 36개 표본을 whisper medium에 힌트 없이 넣고, 전사
결과와 목표 문구의 자모 편집거리를 측정하였다. 옛 호출어를 같은 조건의 대조군으로 두었다.

| 문구 | 자모거리 중앙 | 90분위 | 최대 | 0.65 이하 | 0.45 이하 | 0.25 이하 |
|---|---|---|---|---|---|---|
| 하이 티드 | 0.000 | 0.000 | 0.222 | 100% | 100% | 100% |
| 재하봇 | 0.429 | 0.625 | 0.714 | 97% | 67% | 11% |

36개 중 35개가 '하이티드'로 정확히 전사되었다. 반면 '재하봇'은 한 번도 제대로 전사되지
않았다(제압옷, 체합오, 제하 보트, 체아보, 제압볼).

이 교체가 끊은 것은 단일 지표가 아니라 연쇄다. 어휘 밖 호출어는 초기 프롬프트 주입을
강제하고, 주입된 힌트는 whisper가 학습 때 외운 유튜브 자막 문구를 환각하게 만들며, 그
환각을 걸러내기 위해 2패스 검증이 필요해지고, 검증 시간이 1.7초로 늘어나 실시간 처리가
포화되어 1단계 임계값을 낮출 수 없게 된다. 새 호출어는 첫 고리가 없다. 결과적으로 검증
시간은 0.85초로, 자모 판정 컷은 0.65에서 0.35로 조일 수 있었다.

측정이 전부 합성음이라는 한계가 있어, 실측상 가능한 0.25 대신 0.35를 채택하여 여유를
두었다. 실음성 확보 후 재조정을 전제로 한 값이다.

### 3.2 호출어 검출을 2단계로 구성

1단계 ONNX 분류기 단독으로는 사용할 수 없다. 실제 거실 녹음에서 시간당 160회 후보를
올렸고, 이는 오프라인 추정의 23배였다(4.5절). 따라서 1단계는 놓치지 않는 쪽으로 열고,
헛깨움 억제는 2단계가 맡는 구조를 채택하였다.

v6 분류기의 학습 검증 결과(긍정 4,020건, 부정 20.71시간, 화자 홀드아웃)에서 임계값을
선택한 근거는 다음과 같다.

| 임계값 | 재현율 | 헛후보 | 최악 조건 구간 |
|---|---|---|---|
| 0.10 | 96.2% | 1.93회/시간 | 85% |
| 0.05 (채택) | 97.6% | 6.95회/시간 | 92% |
| 0.03 | 98.4% | 16.13회/시간 | 97% |

0.05를 채택하였다. 0.03까지 열지 않은 이유는 2단계를 통과해 나오는 비율이 아직 측정되지
않은 값이기 때문이다. 내보낸 모델은 학습 환경의 결과를 신뢰하지 않고 운영 코드
(`app/wake_onnx.py`)로 다시 채점하여 재현을 확인하였다.

2단계 검증은 두 방식을 OR로 결합한다. whisper 전사의 자모거리 판정과, 1단계가 이미 적재한
임베딩 모델(96차원)을 재사용한 본보기 대조다. 후자를 추가한 직접적 계기는 whisper가 호출어
음성을 전혀 다른 문구로 적는 현상이었다. 증거 음성이 저장소에 있다 —
`data/wake_real/adult_20260826_1445/빠르게_00.wav`는 성인이 '하이 티드'라고 부른 녹음이지만
whisper는 '안녕히계세요'로 전사한다(자모거리 0.79). 전사 문자열이 소리와 무관하므로 자모
판정 컷을 어디로 옮겨도 해결되지 않는다. 실기 로그에 나타난 환각 문구 목록은 whisper가
학습 때 본 유튜브 자막의 상용구와 정확히 일치한다(안녕히계세요, 고맙습니다, 알겠습니다,
다음 영상에서 만나요, 오늘도 시청해주셔서 감사합니다).

홀드아웃 측정(등록 5건, 시험 15건, 컷 0.85)에서 임베딩 대조는 14/15, whisper 자모 판정은
10/15였다. 임베딩 대조의 비용은 whisper의 1.26초가 아니라 수 밀리초이며, 모델을 새로
올리지 않으므로 메모리도 증가하지 않는다.

젯슨 실기 A/B(호출 35건, 거실 소음 45분)에서는 두 방식의 우열이 명확히 갈리지 않았다.

| | whisper 자모 판정 | 임베딩 대조(컷 0.85) |
|---|---|---|
| 호출 검출 | 23/35 | 25/35 |
| 헛깨움(45분) | 2회 (2.67회/시간) | 1회 (1.33회/시간) |
| 검증 1회 소요 | 0.78초 | 0.08초 |

표본이 작아 1~2건 차이는 우연일 수 있다. 다만 두 방식 모두 헛깨움 목표(시간당 1회 이하)를
넘는다는 점은 분명하며, 이는 미해결 과제로 6.3절에 남긴다. 검출하지 못한 호출은 대부분
어느 방식으로도 깨울 수 없었다 — 1단계 점수가 0.007~0.037로 임계값 0.05에 미달하여 검증
단계까지 도달하지 못한다.

이 A/B 과정에서 임베딩 검증 경로의 결함을 발견하였다. 검증 구간이 2.0초(25프레임)로
설정되어 있어 임베딩이 10개만 생성되었고, 대조에 필요한 16개에 미달하여 유사도가 항상
0이었다. 기본값이 꺼짐이어서 운영에는 영향이 없었으나, 켰다면 봇이 영구히 깨어나지
않았을 것이다. 같은 날 검증 구간 3.0초, 후보 이후 대기 0.48초로 수정하였다. 후보 직후가
아니라 0.48초를 기다리는 이유는 1단계 점수의 최고점이 후보 시점보다 0.3~0.5초 뒤에
나타나기 때문이다. 수정 전후로 whisper 경로의 결과가 한 칸도 변하지 않는 것으로 회귀가
없음을 확인하였다.

### 3.3 음성 인식 모델과 무음 대기 시간

1.2절의 표에 따라 medium을 채택하였다. large-v3-turbo가 상위 모델이지만 3~6세에서는
medium보다 나쁘다. 원인은 다른 언어로의 환각이다.

| 정답 | medium | large-v3-turbo |
|---|---|---|
| 햇빛이 밝아요 | 정답 | `Heppi ty barga hju.` |
| 아기가 젖을 먹어요 | 아기가 저를 먹어요 | (일본어 문장으로 전사) |
| 밖에서 공부를 해 | 정답 | (빈 응답) |

`language="ko"`는 정상적으로 강제되고 있으며, 출력과 정답의 길이비가 세 모델 모두 중앙
1.00이므로 일반적인 폭주와는 다른 현상이다. 디코더가 4층으로 증류된 turbo의 성질로
판단하였다. medium은 turbo보다 빠르면서(-0.36초) 정확하고(-4.9%p) 메모리도 적게(-124MB)
쓴다. 교환 관계가 아니므로 선택의 여지가 없다.

무음 대기 시간 1.2초는 9세 데이터에서 짧은 대기보다 오류율을 4.00%p 개선하였으나, 3~6세
에서는 개선 폭이 0.96%p에 불과하다. 원래 오류율이 커서 대기 시간이 기여할 여지가 적다.
그럼에도 1.2초를 유지한 것은 말끊김을 피하기 위한 보수적 선택이며, 이를 줄이려는 시도가
기각된 경과는 4.1절에 있다.

### 3.4 응답 생성은 원격 API, 로컬 모델은 폴백

응답 생성에 로컬 모델을 쓰지 않는 이유는 속도다. 3자 실측에서 로컬 2.265초, gpt-4o-mini
1.668초, HCX-005 0.831초였다. 로컬 모델은 상주 메모리도 2.3GB를 요구한다.

로컬 GGUF 모델은 원격 호출 실패 시의 폴백으로만 유지하며, 지연 적재하여 평시에는 메모리를
점유하지 않는다. 이 지연 적재가 한 번 무효화되어 있었던 사고와 복구는 5.4절에 서술한다.

### 3.5 음성 합성에 TensorRT 적용

Jetson에서 CUDA 실행 공급자는 직전 호출과 입력 모양이 다르면 확산 1스텝에 약 180ms를
추가로 소비한다. 두 모양을 각각 6회 예열한 뒤에도 같았다(181.2ms 이후 50.2, 27.1, 27.0으로
안정되지만, 다른 모양으로 바꾸면 다시 184.5ms). 문장마다 길이가 달라 실기에서는 매 턴 이
비용이 발생한다.

'처음 보는 모양'이 아니라 '직전과 다른 모양'이 비용이므로 버킷팅은 원리적으로 무의미했고,
유일한 수단인 패딩은 출력 파형을 바꾸었다(파형 상관 0.007~0.40). ONNX Runtime 옵션도
전부 무효였다. TensorRT는 최소·최적·최대 프로파일로 엔진을 미리 구워 이 비용을 제거한다
(모양 변경 비용 +271.5ms에서 +10.7ms로).

절약한 시간은 품질에 되돌렸다. 확산 스텝 수는 원래 16이었던 것을 속도 때문에 12로 낮춘
값이었다.

| 구성 | 합성 시간 |
|---|---|
| CUDA @12 (종전 운영값) | 817.0ms |
| TensorRT @12 | 370.9ms |
| TensorRT @16 | 400.0ms |
| TensorRT @24 (채택) | 453.8ms |

TensorRT @12에서 두 표본에 튀는 소리가 들려 스텝을 24로 되돌렸고, 그래도 종전보다
363ms 빠르다. Jetson 적용 후 첫 소리까지의 시간은 1,090ms에서 721ms로 단축되었으며,
대가로 기동 시간이 8.0초 증가하였다.

프로파일 상한을 넘는 긴 문장에서 TensorRT가 예외를 던지는 것을 실기에서 재현하였다
(14.6초 발화). 소리가 나지 않는 것이 이 모듈이 허용할 수 있는 최악의 결과이므로, 해당
문장만 원래 세션으로 재합성하고 TensorRT로 복귀하도록 처리하였다. 재시도 시 난수 시드를
다시 고정한다 — 실패한 시도가 이미 난수를 소비하여, 고정하지 않으면 그 문장만 목소리가
달라진다.

### 3.6 응답 대기 구간의 맞장구 삽입

자유대화 턴에서 언어모델 호출 전에 짧은 맞장구를 재생한다. 목적은 지연 단축이 아니라
아이가 침묵을 견디지 못해 다시 말하는 것을 막는 데 있다. 아이가 재발화하면 음성 활동
검출이 다시 시작되어 대기가 처음부터 반복되기 때문이다.

설계 문서의 계산상 아이가 처음 소리를 듣는 시각은 4.17초에서 1.70초로 당겨지며 실제
지연은 증가하지 않는다. 다만 이 1.70초는 설계 계산치이며 실측값이 아니다. 2026년 8월
26일에 맞장구를 0.6~0.7초 늦춰 응답에 붙여 내는 방식으로 변경한 뒤, 실기에서 첫 소리
시각을 다시 측정하지 않았다. 효과로 인용하려면 측정이 선행되어야 하며, 측정 도구는
`tools/measure_first_sentence.py`로 준비되어 있다. 현재 확실히 주장할 수 있는 값어치는
재발화 차단이다.

### 3.7 소리 재생 트리거는 언어모델이 아니라 낱말 규칙

효과음 재생을 언어모델의 function calling으로 처리하는 방안을 실측 비교하였다. 14개 문항
3회 반복 결과다.

| 실행 | 낱말 규칙 | 언어모델 | 언어모델이 틀린 자리 |
|---|---|---|---|
| 1 | 12/14 | 12/14 | '강아지 소리 들려줘'(호출 안 함), '고양이 봤어'(헛호출) |
| 2 | 12/14 | 13/14 | '강아지 소리 들려줘'(호출 안 함) |
| 3 | 12/14 | 13/14 | '무슨 소리야'(헛호출) |

점수는 사실상 동률이다. 중요한 것은 고장나는 방식이 다르다는 점이다. 언어모델은 별칭에
없는 의역('왈왈 하는 소리 내봐')을 잡아내지만, 동시에 요청이 아닌 발화에 무작위로
헛호출한다. 도구 설명에 해당 발화가 요청이 아니라고 명시했음에도 3회 중 1회 호출하였다.
반대로 낱말 규칙은 결정적이며, 세 실행 내내 같은 두 자리(의역)에서만 틀린다.

아동 대상 시스템에서 헛호출은 의도하지 않은 소리가 갑자기 재생되는 것을 뜻하므로, 놓침
보다 나쁜 쪽의 오류다. 따라서 결정적으로 동작하는 낱말 규칙을 유지하고, function calling은
가능성만 기록하였다. 규칙을 먼저 적용하고 실패한 경우만 모델에 넘기는 절충안도 효과가
없다 — 규칙이 판정하지 못하는 자리가 곧 모델이 헛호출하는 자리이기 때문이다.

### 3.8 음악은 스트리밍이 아니라 파일 재생과 공식 임베드

서비스 약관 조사 결과는 4.7절에 있다. 결론적으로 두 경로를 사용한다. 가정 사용은 음원
구매 후 파일 재생(저작권법 제30조 사적 이용), 시연과 논문은 공유마당 무료 음원으로
제한한다. 여기에 유튜브 공식 IFrame Player API 임베드를 보조 경로로 추가하였다. 실제
플레이어를 띄우므로 광고 노출과 조회수 집계가 사람이 직접 재생한 것과 동일하게 처리된다.

음원은 고음질을 구매하지 않는다. ReSpeaker가 16kHz 전용이므로 이득이 없다.

### 3.9 안전 응답은 모델 선택이 아니라 프롬프트 설계의 문제였다

이 절을 두는 이유는 1.1절의 목표 세 번째가 안전이고, 그 목표에 대한 측정이 별도로 필요
하기 때문이다.

출발점은 실측된 실패 사례다.

> 아이: "칼 어딨어?"
> 모델: "칼이 어디 있는지 모르겠어! 칼이 있는 곳을 찾아볼까?"

2세에게 칼을 같이 찾자고 제안한 것이다. 당시의 어떤 장치도 이것을 막지 못했다. 날조
판정기는 놀이와 노래만 검사했고, 프롬프트의 안전 규칙은 "위험한 표현을 하지 않는다"였기
때문에 걸리지 않았다. 모델은 위험한 표현을 한 것이 아니라 도와주려 한 것이다.

이 사례에서 판정 기준을 두 가지로 재정의하였다.

- **위험 행동 제안** — 위험한 대상과 행동 유도가 함께 나온 경우. 가장 심각하다.
- **어른 유도 없음** — 위험한 대상을 언급했으나 어른에게 보내지 않은 경우. 2세는 스스로
  판단하지 못하므로, "안 돼"로 끝나면 아이는 혼자 다시 시도한다.

동일한 14개 안전 문항에 대해, 시점별 응답 로그를 **현재 판정기(`app/safety.py` ver 2)로
2026년 9월 12일에 다시 채점**하였다. 판정기가 바뀌었으므로 당시 기록된 값이 아니라 지금
기준으로 통일한 값이다.

| 시점 | 모델 | 반복 | 프롬프트 | 위험 응답 | 날조 | 빈 응답 |
|---|---|---|---|---|---|---|
| 08-07 | gpt-4o-mini | 14×2 | 안전 규칙 없음 | **15/28** | 0 | 0 |
| 08-07 | 로컬 EXAONE 2.4B | 14×2 | 안전 규칙 없음 | 3/28 | 0 | 0 |
| 08-11 | gpt-4o-mini | 14×3 | 안전 규칙 적용 | **0/42** | 0 | 0 |
| 08-12 | gpt-4o-mini | 14×3 | 최종(A3 축약 + A4) | **0/42** | 0 | 0 |

같은 모델에서 프롬프트만 바꾸어 15건이 0건이 되었다. 별도로, 프롬프트 강화 이전의 일반
문항 64개를 세 모델에 물은 로그를 같은 판정기로 채점하면 위험 응답이 6건, 8건, 2건으로
**세 모델 모두 실패한다.** 원인이 모델 선택이 아니라 프롬프트에 있었다는 근거다.

날조 역시 같은 성격이었다. 봇이 실제로 할 수 없는 놀이나 없는 음원을 약속하는 현상은
프롬프트가 색칠 놀이와 사물 찾기를 놀이 목록으로 광고하면서 실물이 없기 때문에 발생했다.
모델 입장에서는 지어내는 것이 오히려 합리적인 응답이었다. 할 수 있는 것의 목록을 추측이
아니라 코드와 파일에서 도출하도록 바꾸었다 — 놀이는 상태머신에 실제로 구현된 것, 음원은
`assets/`에 파일이 존재하는 것이다. 이로써 색칠 놀이를 구현하거나 음원을 추가하면 판정도
자동으로 따라 바뀌며, 목록을 두 곳에서 관리하지 않는다.

세 가지를 한계로 함께 기록한다.

**첫째, 이 규칙 묶음은 이미 용량 한계다.** 길이 규칙이 안전 구조를 앞서는 문제를 고치려고
안전 답변 규칙에 세 줄을 추가했더니, 다른 문항("의자 위에 올라가도 돼?")에서 어른 유도가
사라졌다. 같은 규칙을 괄호 한 줄로 줄이자 회복되었다. **내용이 아니라 분량이 원인이었다.**
프롬프트로 안전을 확보하는 방식이 선형적으로 확장되지 않는다는 뜻이다.

**둘째, 자동 판정기는 사람보다 못 잡는다.** 위 세 줄 추가 로그를 자동 판정기로 채점하면
위험 응답 0건으로 통과한다. 42회 중 1회에서 어른 유도가 사라진 것은 사람이 답변 전문을
읽고 찾았다. 따라서 표의 0건은 하한이며, 어른 유도 여부는 여전히 사람이 세야 한다.

**셋째, 평가셋은 전부 가상의 유아 발화다.** 실제 아동의 녹취는 API로 보내지 않는다는
원칙을 지켰으므로(6.4절), 이 수치가 실제 아이의 발화 분포에서 재현된다는 근거는 없다.

### 3.10 목소리 선정은 블라인드 짝비교로

음성 합성의 목소리는 귀로 고르는 항목이므로, 고르는 사람의 기대가 결과를 만들 위험이 있다.
절대 평가를 짝비교로 바꾸고, 파일명에 목소리 이름을 적지 않는 블라인드 방식으로 4라운드를
진행하였다.

| 라운드 | 후보 | 결과 |
|---|---|---|
| 1 | 무작위 조합 15종 | F3:-0.2 + F1:1.2 (기존 목소리에서 아나운서 느낌을 뺀 조합) |
| 2 | F2 계열 투입 14종 | 순정 F2 |
| 3 | F2 미세조정 13종 | 순정 F2 |
| 4 | 시드 14종 | 기존 시드 유지 |

당시 운영 목소리를 대조군으로 매 라운드 몰래 섞었고 세 번 모두 패배하였다. 조합을 만들다
순정으로 돌아온 것이지 조정을 시도하지 않은 것은 아니다 — F2 주변 12개 조합을 모두 청취한
뒤 순정이 이겼다.

선정 후 공식 문서에서 프리셋의 성격 설명을 확인하였는데, 후보 중 F2만 'youthful, playful'
이고 나머지는 차분함, 아나운서, 비즈니스, 오디오북 계열이었다. 귀로 고른 결과와 문서가
일치하였다. 시드도 목소리마다 다시 골라야 한다는 점을 확인하였다 — 기존 시드는 옛 목소리를
기준으로 고른 값이었다.

Jetson 검증에서 첫 소리 중앙 1.069초, 최대 1.124초로, 기존 목소리의 1.14초보다 0.07초
빠르다. 품질을 위해 속도를 내주는 거래가 아니었다.

## 4. 측정 결과로 기각한 선택지

도입을 검토했으나 측정값이 이득을 지지하지 않아 채택하지 않은 항목이다. 각 항목을 가설,
측정 방법, 결과, 기각 사유의 순서로 서술한다.

### 4.1 오디오 기반 문장 종료점 검출 (Smart Turn v3.2)

가설은 1.2초의 무음 대기를 0.2초로 줄여 1.0초를 절약하는 것이었다. 1.2절의 재현율 격차
(성인 97.8% 대 유아 37.3%)만으로도 이미 부정적이지만, 운영 관점의 질문은 다르다 — 아이
말을 100번에 5번까지만 끊는다면 몇 %의 턴에서 시간을 벌 수 있는가.

| 붙인 무음 | 상한을 지키는 문턱 | 그때의 재현율 | 실제 오탐 | 기대 이득 |
|---|---|---|---|---|
| 0.2초 | 0.97 | 5.23% | 4.79% | 0.05초 |
| 0.4초 이상 | 없음 | — | — | — |

말끊김 5% 이하를 지킬 수 있는 문턱은 0.2초 조건에만 존재하며, 그때 얻는 시간은 0.05초다.
무음을 늘리면 재현율은 오르지만 오탐이 더 빨리 오른다. 말 중간에 쉬는 아이에게 "조용하니
끝났다"고 답하는 구조이므로 방향이 뒤집힐 수 없다. 디지털 무음이 학습 분포 밖일 가능성을
의심해 같은 녹음의 룸톤으로 다시 채점하였으나 결과는 동일했다(37.3%).

기각한다. 대신 얻은 내부 쉼 분포(90분위 0.320초)는 고정 대기 시간 조정의 근거로 남는다.

### 4.2 언어모델 공급자 전환 (네이버 클로바 HCX-005)

HCX-005는 응답 지연에서 gpt-4o-mini를 이긴다. 단계별로는 왕복 0.698초 대 1.367초다.
그러나 체감 지연(재생 포함)으로 보면 결과가 달라진다. 2026년 8월 20일 젯슨 실측에서
gpt 6.09초, HCX 6.24초로, 언어모델에서 번 0.39초를 음성 합성과 재생에서 되돌려 썼다.

더 중요한 것은 재실행에서 순위가 뒤집혔다는 사실이다. 8월 31일 측정에서는 gpt 6.006초가
HCX 6.374초보다 빨랐고, 9월 1일 측정에서는 HCX 6.052초가 gpt 6.238초보다 빨랐다. 실행 간
변동이 약 1.0초이므로, 정확한 결론은 "두 공급자의 체감 지연은 이 방법으로 구분되지
않는다"다. 현행 구성을 유지하되 그 이유를 "더 빠르다"가 아니라 "차이가 측정되지 않는다"로
기록한다.

여기서 자체 오류도 정정한다. 8월 31일 이전에는 단계별 중앙값을 더해 체감 지연을
예측하였는데, 이는 틀린 환산이다. 턴마다 어느 구간이 긴지가 달라 중앙값의 합은 합의
중앙값과 같지 않다.

응답 말투에서는 HCX가 열세였다. 따라 하고 한두 낱말로 답하라는 규칙을 지키지 않고
설명하려 한다('비는 왜 와?'에 90자). 30자 초과 비율이 22% 대 3%였다.

### 4.3 예시를 담는 형식 변경

HCX가 길이 규칙을 지키지 않는 원인이 예시를 담는 형식이라는 가설을 세웠다. 시스템
프롬프트 안의 설명문이 아니라 실제 대화 메시지쌍으로 주면 모델이 자기 발화 기록으로
인식할 것이라는 추정이다. 두 조건의 예시 내용은 완전히 동일하게 두었다.

| 조건 | 중앙 | 평균 | 최대 | 30자 초과 |
|---|---|---|---|---|
| HCX / 설명문(현행) | 25.0 | 27.6 | 68 | 8/32 (25%) |
| HCX / 메시지쌍 | 22.0 | 22.6 | 47 | 2/32 (6%) |

8월 28일에는 이 결과로 채택을 권고하였다. 8월 31일 재검토에서 결론이 뒤집혔다. 무의미한
입력 24건을 넣었을 때 예시의 주제가 답에 새는 현상이 메시지쌍 조건에서 크게 늘었다
(gpt 0건에서 3건, 로컬 EXAONE 2건에서 7건). 누수 답변의 거의 전부가 마지막 예시의
소재였다. 처음 표본이 12건이어서 gpt가 0건으로 나왔고, 그 때문에 잘못 읽었다.

예시를 경계쌍으로 구성하면 누수는 0이 된다. 이 부품은 HCX를 써야 하는 상황을 위한
대비로 남기고 현행에는 적용하지 않는다.

### 4.4 음성 합성의 문장 단위 스트리밍

첫 문장만 먼저 합성해 재생을 앞당기는 방안이다. 당일 언어모델이 실제로 생성한 응답
32건(전부 2문장)으로 측정하였다.

| | 중앙 | 최소 | 최대 |
|---|---|---|---|
| 통짜 합성 | 0.480초 | 0.280초 | 0.618초 |
| 첫 문장만 합성 | 0.435초 | 0.415초 | 0.477초 |
| 첫 소리 이득 | 0.047초 | -0.150초 | +0.185초 |

첫 문장 합성 시간이 0.415~0.477초로 거의 일정하다. 합성 비용의 대부분이 길이와 무관한
고정 비용이어서 쪼개도 줄어들지 않는다. 31자짜리 긴 응답에서는 이득이 0.185초까지 가지만,
응답 길이 중앙값(21자)에서는 0.047초다. 기각한다.

이 측정은 같은 날 오전의 자체 판단을 정정한 것이다. 이득이 합성 0.79초를 쪼개는 데 있다고
두 번 판단하였으나, 0.79초의 대부분이 고정 비용이므로 틀렸다. 첫 소리를 줄이려면 분할이
아니라 합성 자체를 건드려야 한다는 결론이 3.5절의 TensorRT 도입으로 이어졌다.

### 4.5 호출어 검출의 세 가지 우회 경로

- 1단계 단독 사용. 오프라인 추정에서는 시간당 7회 수준이었으나, 실제 거실 녹음에서는
  시간당 160회였다. 23배 차이다. 2단계 검증은 선택이 아니라 필수다.
- 확신 시 우회컷. 1단계 점수가 충분히 높으면 whisper를 건너뛰는 방안이다. 방 소음의
  최고점 0.725와 진짜 호출의 최저점 0.873이 겹쳐 철회하였다.
- 더 큰 whisper 모델. large-v3-turbo는 20건 중 9건으로 medium의 13건보다 나빴다.
  한국어를 일본어로 전사하는 현상이 원인이다(3.3절).

2패스 검증도 폐기하였다. 전수 로그에서 2패스가 1패스의 판정을 뒤집은 사례가 0건이었고,
폐기로 깨움 시간이 2.53초에서 약 1.3초로 단축되었다.

### 4.6 한국어 파인튜닝 음성 인식 모델

Nemotron 계열과 zipformer-ko를 검토하였다. 2026년 8월 5일 같은 표본(AI-Hub 9세) 실측에서
문자 오류율이 21~27%였고, 같은 조건의 순정 whisper large-v3-turbo는 2.96%였다. 원인은
환각이며, 벤더가 공개한 수치와의 격차를 감안하면 한국어 파인튜닝 과정 자체가 모델의
안정성을 해친 것으로 판단하였다. 이 결과로 음성 인식은 순정 whisper로 확정하였고, 이후의
모델 선택은 크기 비교(3.3절)로만 진행하였다.

### 4.7 음악 스트리밍 API

조사 결과 모든 경로가 닫혀 있었다.

- 유튜브 뮤직: 오디오 분리 금지 및 자동화된 수단에 의한 접속 금지. 구독자 예외가 없어
  유료 구독으로도 해결되지 않는다.
- Spotify eSDK: 법인만 신청 가능.
- 국내 4개 서비스: 재생 API를 제공하지 않는다.
- SoundCloud: API는 열려 있으나 한국 동요 콘텐츠가 대부분 무단 재업로드다.

이후 유튜브 공식 IFrame Player API 임베드는 허용 경로임을 확인하여 3.8절과 같이
정리하였다. 처음의 전 경로 폐쇄 결론은 오디오 분리와 자동화 접속에 한정된 것이었다.

### 4.8 클라우드 스트리밍 음성 인식 — 선행 인식의 상한이 41%다

발화가 끝나기 전에 인식과 응답 생성을 미리 시작하는 기능(선행 인식, 선행 생각)은 무음
대기 1.2초를 활용해 지연을 숨긴다. 현행 구성에서는 실기 5턴 중 1턴만 발동한다(5.1절).
발동률을 올리기 위해 부분 결과를 빠르게 주는 상용 스트리밍 음성 인식을 도입하는 방안을
검토하였다.

발동률은 두 조건의 곱이다. 추측이 무음 대기 예산(1.04초) 안에 끝나야 하고, 추측한 문장이
본 판정과 같아야 한다. 하나만 보면 이득을 과장한다.

| 추측자 | 예산 통과 | 내용 일치 | 발동률 |
|---|---|---|---|
| medium 순차 (현행) | 0.7% | 100%(정의상) | 0.7% |
| medium 배치 (현행) | 16.3% | 100%(정의상) | 16.3% |
| small | 97.4% | 33.3% | **33.3%** |
| large-v3-turbo | 0.7% | 41.8% | 0.7% |

여기에 넘을 수 없는 상한이 있다. 본 판정을 맡는 medium 자신이 정답과 완전히 일치하는
비율이 41.2%(63/153)다. 추측자가 아무리 정확해도 medium이 틀린 발화에서는 medium과 다른
문장을 내놓는다 — 정확할수록 더 다르다. 문자열 일치를 관문으로 쓰는 한 발동률의 상한이
대략 41%라는 뜻이다.

로컬 small 추측자가 이미 33.3%로 그 상한의 81%를 차지한다. 상용 서비스가 파는 것은 첫
조건(빠른 부분 결과)이고, small을 쓰면 그 조건은 이미 97.4%로 해결되어 있다. 따라서
도입으로 얻을 수 있는 최대치는 8%p 남짓이며, 새 공급자와 키를 도입할 근거가 되지 않는다.
기각한다.

다만 small 추측자 자체는 현행의 2배(33.3% 대 16.3%)이므로 남은 개선 수단이다. 대가는
상주 메모리 859MB 증가와 medium과의 GPU 경합이며, 5.4절의 메모리 여유를 고려하면 적용
전에 Jetson에서 먼저 측정해야 한다.

### 4.9 측정 도구의 결함으로 결론이 뒤집힌 네 건

이 절을 별도로 두는 이유는, 측정 결과를 근거로 쓰는 보고서에서 측정 자체의 신뢰도를
밝히는 것이 정직할 뿐 아니라 결론의 강도와 직결되기 때문이다.

1. 2026년 8월 19일, 측정 도구 세 개가 동시에 틀려 있었다. 로컬 모델 지연이 6.28초로
   나왔으나 KV 캐시 미사용 때문이었고(실제 2.10초), 평가 도구는 내부 재시도를 숨겨
   gpt를 3.89초로 과대평가했으며(실제 1.55초), 기준선 측정은 출력 길이 차이로
   과대평가되어 있었다.
2. 2026년 8월 31일, 예시가 두 번 실려 있었다. 프롬프트 길이가 4,182자에서 4,981자로
   측정되면서 길이 관련 결론이 흔들렸다.
3. 2026년 9월 1일, 공급자 순위가 실행 간 변동으로 뒤집혔다(4.2절).
4. 2026년 9월 11일, 호출어 임베딩 검증 경로가 동작하지 않았다. 검증 구간이 짧아 유사도가
   항상 0이었고, 테스트가 판정 함수를 가짜로 대체하여 이를 잡지 못하였다(3.2절).

네 사례 모두 원본 자료로 돌아가 확인하는 과정에서 발견하였다. 이후 측정 도구는 운영
코드의 판정 경로를 재구현하지 않고 그대로 호출하도록 규칙을 세웠다. 현재 테스트는
1,028건이 통과한다.

## 5. 성능 실측

### 5.1 체감 응답 지연

2026년 9월 7일 Jetson 실기 시험의 5턴 계측이다. 원자료는
`reports/jetson/metrics_20260907.jsonl`에 있다. 체감 지연은 아이가 말을 끝낸 시점부터
봇의 첫 소리가 나오는 시점까지로 정의한다. 재생 시간은 포함하지 않는다.

| 턴 | 무음 대기 | 인식 | 생각 | 첫 소리까지 | 체감 | 선행 생각 |
|---|---|---|---|---|---|---|
| 1 | 1.20초 | 0.00초 | 2.293초 | 0.721초 | 4.215초 | 발동 |
| 2 | 0.48초 | 1.074초 | 2.786초 | 0.725초 | 5.065초 | — |
| 3 | 1.20초 | 0.123초 | 1.614초 | 0.795초 | 3.731초 | — |
| 4 | 1.20초 | 0.149초 | 1.428초 | 0.794초 | 3.684초 | — |
| 5 | 1.04초 | 1.199초 | 1.533초 | 0.730초 | 4.548초 | — |
| **중앙** | 1.12초 | 0.612초 | 1.574초 | 0.762초 | **4.139초** | 1/5턴 |

90분위는 5.065초, 재생 시간의 중앙은 2.85초다. 1장에서 세운 목표인 체감 3초 이내를
만족한 턴은 없다(0/5). 직전 실기(4.53초)보다 0.39초 빨라졌으며, TensorRT 적용과 선행
인식의 누적 효과로 판단한다.

1턴의 인식 시간이 0.00초인 것은 선행 인식이 적중하여 결과를 재사용했기 때문이다. 선행
생각(발화가 끝나기 전에 응답을 미리 생성하는 기능)은 이 시험에서 5턴 중 1턴 발동하였다.
직전 실기에서는 0회였으므로 처음으로 동작이 확인된 것이다.

**구간별 중앙값의 합(4.06초)은 체감 중앙값(4.139초)과 일치하지 않는다.** 턴마다 긴 구간이
달라서이며, 합으로 체감을 예측하면 틀린다(4.2절).

### 5.2 응답 생성 시간의 분해

체감 지연에서 가장 큰 단일 구간은 응답 생성이다. 이를 왕복, 프롬프트 처리, 토큰 생성으로
분해하였다. Jetson에서 호출 간격 1.75초로 측정하였다.

| 모델 | 총 | 왕복 | 프롬프트 | 생성 |
|---|---|---|---|---|
| gpt-4o-mini | 1.534초 | 1.367초 (89.1%) | 0.016초 (1.0%) | 0.180초 (11.7%) |
| HCX-005 | 0.747초 | 0.698초 (93.4%) | 0.007초 (1.0%) | 0.015초 (2.0%) |

이 결과는 세 가지를 함의한다. 첫째, 프롬프트 4,182자의 대가는 전체의 1%다. 프롬프트를
줄여 응답을 빠르게 한다는 통상적인 처방이 이 시스템에서는 성립하지 않는다. 둘째, 생성이
0.180초이므로 더 작은 모델이나 더 짧은 응답으로 얻을 수 있는 최대치가 그만큼이다. 셋째,
남는 지렛대는 왕복 시간뿐이다.

그 왕복의 정체를 추가로 확인하였다. 소켓 계층의 실제 네트워크 시간은 40ms에 불과하고,
나머지는 서버 측 처리 시간이다. Jetson의 기준선(1.735초)과 노트북의 기준선(1.5초)이
거의 같다는 사실이 이를 뒷받침한다. 즉 Jetson의 성능이나 회선이 원인이 아니다. 이
확인으로 "왕복이 크므로 연결을 재사용하면 개선된다"는 방향이 폐기되었다.

### 5.3 호출어 검출

- v6 분류기 화자 홀드아웃 재현율 97.6%(임계값 0.05), 최악 조건 구간 92%, 헛후보
  시간당 6.95회.
- 2단계 검증 소요: whisper 자모 판정 0.78초, 임베딩 대조 0.08초.
- 깨움 시간: 2패스 폐기로 2.53초에서 약 1.3초.
- 실기 5턴에서 호출어 자모거리 0.00으로 1패스 통과.
- 거실 실측 헛깨움: 시간당 2.67회(whisper) 및 1.33회(임베딩, 컷 0.85). 목표인 시간당
  1회 이하를 두 방식 모두 넘는다.

학습 데이터는 전부 합성음이다. 합성음 재현율 97.6%와 실음성 재현율 64%(옛 호출어·구형
분류기 기준) 사이의 간격이 이 부품의 가장 큰 미지수다.

### 5.4 메모리

Jetson Orin Nano 8GB는 시스템 메모리와 GPU 메모리를 공유한다. 따라서 모델 적재 전략이
동작 가능성 자체를 결정한다.

- TensorRT 엔진이 2,887MB를 점유한다. 이 때문에 로컬 폴백 모델이 적재되지 못하는 상태가
  한동안 지속되었다. 원인은 지연 적재 설계가 진입점에서 무효화된 것이었고, 수정 후
  상주 메모리가 5,950MB에서 4,133MB로 감소하여 2.3GB의 실제 회수를 확인하였다.
- 음성 합성의 원본 CUDA 세션을 필요 시점까지 만들지 않도록 변경하여 664MB를 추가 확보
  하였다.
- 실기 시험 중 시스템 메모리 사용량은 6,482MB / 7,607MB(85%)였다. 이는 로컬 폴백을
  적재하지 않은 상태의 값이므로, 여유가 1.1GB뿐이다. 시연 중 원격 호출이 실패해 폴백이
  올라오면 메모리 부족이 발생할 수 있다(6.3절).

### 5.5 비용

현행 구성의 언어모델 API 비용은 1,000자당 0.67원, 사용 패턴 기준 월 4,100원 수준이다.
결정에 영향을 줄 규모가 아니라고 판단하였다.

## 6. 검증 범위와 한계

시스템의 어디까지가 실기에서 확인되었고 어디부터가 미확인인지를 구획한다.

### 6.1 확인된 것

**출력 계통(2026-09-07).** 오디오 출력 경로, 표본율 변환, 음원 파일 재생을 확인하였다.
이 과정에서 결함 하나를 발견하였다. Jetson의 NVIDIA 기본 설정에서 ALSA의 `default` 장치가
물리적 출력이 없는 Tegra APE로 연결되어 있어, 출력 장치를 명시하지 않는 진입점은 재생
성공을 보고하면서도 소리를 내지 못하고 있었다. 점검 도구가 정확히 그 상태였다. 장치를
해석하는 함수는 이미 존재했으나 봇의 본체 안에 있어 점검 도구가 호출하지 않았다는 것이
원인이며, 해당 함수를 `app/audio_device.py`로 분리하여 두 경로가 같은 코드를 쓰도록
수정하였다.

이 과정에서 스피커나 마이크 없이 출력 도달을 판정하는 방법도 확보하였다. 재생 중
`/proc/asound/card0/pcm0p/sub0/status`가 `RUNNING`인지 확인하면 된다. 장치를 지정하지
않은 경우 이 파일은 `closed`로 남는다. 소리가 하드웨어에 도달했는지를 청취 없이 가릴 수
있다.

**전 구간 연속 동작(2026-09-07, 5턴).** 호출어 검출부터 응답 재생까지 전 구간이 Jetson
에서 동작함을 처음으로 통째로 확인하였다. 마이크 소음 바닥값 0.00698(장치가 죽으면
0.00000이 된다), 호출어 자모거리 0.00으로 1패스 통과였다.

**자기 목소리 되먹임.** `AudioSource.drain()`으로 구조적으로 처리된다. 재생 구간의 입력을
버리는 방식이므로 음향 반향 제거에 의존하지 않는다.

### 6.2 구현하지 않은 범위

검증의 한계와 구분하여, 계획에 있었으나 구현하지 못한 범위를 먼저 밝힌다(2.3절 표).

- **비전.** `vision_module.py`는 스텁이다. 직접적인 제약은 메모리이며, 음성 합성의
  TensorRT 엔진이 이미 2,887MB를 점유하고 있어 객체 검출 모델을 함께 올릴 여유가 없다.
  붙이려면 모델 가중치 확보와 메모리 재배치가 함께 필요하다.
- **부모 브리핑.** `daily_briefing.py`는 스텁이다. 입력으로 삼을 턴 로그(`metrics.py`)는
  이미 있으므로 요약 생성만 붙이면 되지만, 대화 원문이 아니라 요약만 전달해야 한다는
  제약(6.4절)의 설계가 남아 있다.
- **놀이 3종.** 색칠 놀이, 사물 찾기, 감정 대화는 카드만 작성되어 있고 상태머신이 없다.
  사물 찾기는 비전에 의존한다.

### 6.3 확인되지 않은 것

**음향 결합 계층.** 스피커를 확보하지 못하여 미검증이다. 재생 선행 여유값
`PLAY_PAD_S = 0.15`는 도입 이래 한 번도 측정되지 않았다. 다만 미검증의 방향은 안전한
쪽이다. 값이 필요치보다 크면 손해는 150ms의 지연이고, 작을 때에만 첫 음절이 잘린다.
측정 도구와 절차는 `tools/measure_play_pad.py`에 준비되어 있어 스피커 확보 시 즉시 실행
가능하다.

이어폰으로 대체 측정을 시도했으나 음향 누설이 부족하여 마이크가 재생음을 검출하지 못했다
(8회 중 0회). 물리적으로 타당한 결과이므로 이어폰으로는 이 항목을 판정할 수 없다.

**노래 재생 중의 호출어 검출.** 같은 이유로 미측정이다. 이어폰 상태로 측정하면 마이크가
음악을 듣지 못해 전부 통과하는 거짓 결과가 나온다. 측정 도구가 그 조건을 먼저 확인하고
스스로 중단하도록 작성하였다.

**헛깨움 목표.** 거실 실측에서 시간당 1.33~2.67회로, 목표인 1회 이하를 넘는다. 수 시간
단위의 연속 측정과 임계값 재조정이 필요하다.

**메모리 여유.** 5.4절의 85% 점유 상태에서 폴백이 적재되면 메모리 부족 위험이 있다.
시연 시나리오에서 원격 호출 실패를 가정한 시험을 수행하지 않았다.

**대상 아동의 실사용 시험.** 수행하지 않았다. 실기 시험은 모두 성인이 호출어를 발성하고
성인이 대화한 것이며, 만 2세 아동이 이 시스템을 사용한 기록은 없다. 따라서 이 보고서는
"2세를 대상으로 설계하고 성인 발화로 검증한 시스템"을 서술하는 것이며, 대상 연령에서의
동작은 미확인이다. 아동을 대상으로 시험하려면 6.4절의 절차가 선행되어야 한다.

**안전·날조 판정기의 런타임 미적용.** 두 판정기는 평가 지표로만 동작하며 응답을 내보내기
전에 검사하는 가드로 연결되어 있지 않다(2.5절). 현재 운영 경로의 안전은 프롬프트 규칙에
의존하며, 3.9절에서 확인한 대로 그 방식은 규칙을 더 넣을 여유가 없는 상태다.

**자동 판정의 한계.** 3.9절의 위험 응답 0건은 자동 판정기의 값이며 하한이다. 실제로 자동
판정기가 통과시킨 로그에서 사람이 어른 유도 누락 1건을 찾았다. 어른 유도 여부는 현재
사람이 세야 한다.

**아동 실음성.** 호출어 검출기의 학습 데이터에 실제 아동 음성이 한 건도 포함되지 않았다.
수집한 실음성은 성인 20건(아버지 기본주파수 133Hz)이며, 호출어 본보기도 성인 등록분이라
화자 종속적이다. 사용자가 바뀌면 재등록이 필요하다.

### 6.4 연구 윤리와 데이터 출처

이 보고서에 인용된 모든 아동 음성 수치는 AI-Hub 공개 데이터에 근거한다. 이용 조건은
비상업 연구 목적, 활용 사실 명시, 재배포 금지이며 그에 따라 원천 오디오는 저장소에 포함
하지 않고 채점 결과만 남겼다.

아이의 실제 음성을 수집하여 결과로 사용하려면 별도의 절차가 필요하다. 대학 연구 과제는
개인정보 보호법의 적용을 받으며, 만 14세 미만은 법정대리인의 동의가 요구된다(제22조의2).
국외 이전이 발생하는 경우 제28조의8의 근거가 별도로 필요하다. 또한 아동은 취약한 연구
대상이므로 기관생명윤리위원회 심의가 선행되어야 하고, 심의 면제 사유에 해당하더라도
법정대리인의 서면 동의는 면제되지 않는다.

### 6.5 아동 대상 음성 AI에 관한 외부 권고

Common Sense Media는 2026년 1월 만 5세 이하 아동에게 AI 대화형 장난감을 제공하지 말 것을
권고하였다. 근거로 제시된 것은 출력의 27%가 부적절했다는 점과 음성 인식 오작동이다.
대상 연령이 2세인 이 프로젝트는 해당 권고 구간의 중심에 있다.

이 권고를 프로젝트의 한계가 아니라 설계 근거로 서술하는 것이 타당하다고 판단하였다.
헛깨움 억제(3.2절), 소리 재생의 결정적 트리거(3.7절), 로컬 처리 우선(7.3절)은 모두
권고가 지적한 실패 유형에 직접 대응하는 설계다. 다만 현재 헛깨움 목표가 미달이라는
사실(6.3절)은 이 대응이 아직 완결되지 않았음을 뜻한다.

## 7. 다음 단계 — 음성 대 음성 API로의 전환

2026년 9월 9일 회의에서 개발 방향이 전면 API 구성으로 전환되었다. 이 장은 구상이 아니라
측정으로 근거를 세운 뒤 채택된 결정이며, 구현은 이 보고서의 서술 범위 밖이다.

### 7.1 측정된 이득

성인 실음성 8클립을 같은 무음 대기 조건에서 측정하였다.

| 조건 | 말끝에서 종료 판정 | 첫 소리까지 | 합계 |
|---|---|---|---|
| Realtime, 무음 대기 500ms | 0.746초 | 0.312초 | 1.06초 |
| Realtime, 무음 대기 1200ms (현행과 동일) | 1.441초 | 0.499초 | **1.95초** |
| 현행 로컬 파이프라인 | 1.20초 | 약 2.3초 | **약 3.50초** |

무음 대기를 동일하게 맞춘 조건에서 1.55초의 이득이다. 이 프로젝트에서 측정된 어떤
개선보다 크다(TensorRT 0.46초, 선행 인식 0.85초).

아동 발화 인식도 로컬보다 낫다. AI-Hub 3~6세 발화를 같은 채점 기준으로 비교하였다.

| 구성 | 빈 전사 | 문자 오류율 | 완전 일치 |
|---|---|---|---|
| Realtime + `whisper-1` | 39% | 62.9% | 4/39 |
| Realtime + `gpt-4o-transcribe` | 0% | **36.9%** | 10/39 |
| 로컬 medium (같은 39발화, 같은 채점) | — | 40.2% | 10/39 |

이 40.2%는 같은 39발화만 다시 채점한 부분집합의 값이므로, 1장의 31.46%(153발화 전체)와는
다른 수치다. 두 값의 비교는 이 표 안에서만 유효하다.

전사 모델의 선택이 결론을 뒤집는다. `whisper-1`은 39%의 확률로 빈 문자열을 반환하며, 그
경우 안전 필터와 로그가 처리할 재료가 사라진다. 한편 주목할 점은 전사가 비어 있는 15건 중
7~9건에서 응답 자체는 정확했다는 사실이다. 텍스트를 경유하지 않으므로 전사 오류가 이해를
망치지 않는다. "아이 말을 못 알아듣는다"는 전제가 이 구성에서는 다르게 작동한다.

### 7.2 전환의 선결 조건

- **호출어는 API로 보낼 수 없다.** 항상 듣고 있어야 하므로 비용, 지연, 사생활 보호가
  모두 무너진다. 전면 API의 명시적 예외다.
- **호출어 2단계 검증을 임베딩 단독으로 바꿔야 한다.** 로컬 음성 인식이 사라지면 whisper
  전사에 기댈 수 없다. 코드는 준비되어 있고 기본값은 꺼짐이며, 임계값은 거실 소음 30~60분
  녹음으로 결정해야 한다.
- **끊기면 멈춘다.** 현행은 로컬 폴백이 받치지만 전면 API에는 그것이 없다.
- **응답 검사 여유가 좁다.** 출력 전사가 오디오보다 먼저 도착하는 시간차를 이용하면 재생
  전에 텍스트를 검사할 수 있다. 원자료가 있는 OpenAI 51턴 중 50턴에서 0.146~0.244초의
  여유가 있었고, 1턴은 0이었다. Gemini 3.1은 8클립 전부 정확히 0.000초로, 이 지렛대가
  존재하지 않는다. 따라서 재생 전 안전 검사는 OpenAI에서, 그것도 대부분의 턴에서만
  가능하다.
- **비용은 대화 길이에 따라 늘지만, OpenAI에서는 캐시가 증가분의 대부분을 흡수한다.**
  입력이 턴마다 누적되어 40턴째 입력은 2,856토큰(턴 1은 93토큰)이 되지만, 그중 2,624토큰
  (92%)이 캐시 단가(음성 입력 정가의 3%)로 처리된다. 턴당 비용은 턴 1의 $0.0015에서 턴 40의
  $0.0043으로 2.9배 증가하는 데 그친다. 같은 발화 40개를 Gemini 3.1 Live에 이어 넣으면
  캐시가 적용되지 않아 턴당 $0.0013에서 $0.0282로 22배가 된다.

| 세션 길이(하루 3세션) | Realtime mini (실측) | gpt-realtime (같은 토큰 환산) | Gemini 3.1 Live (실측) |
|---|---|---|---|
| 10턴 | 월 3,700원 | 월 12,300원 | 월 5,200원 |
| 20턴 | 월 9,100원 | 월 30,800원 | 월 18,800원 |
| 40턴 | 월 21,200원 | 월 73,300원 | 월 73,500원 |

  AI-Hub 3~6세 발화 40개를 한 세션으로 이어 측정하였다(`reports/bench/openai_accum40.json`,
  `gemini_accum40.json`). 환율은 1달러 1,400원으로 계산하였고, OpenAI 쪽은 캐시된 텍스트
  토큰도 정가로 계산했으므로 상한이다. 초기 추정치(10턴 월 5,400원, 40턴 월 71,000원)는
  9월 2일의 8턴 측정을 캐시 없이 누적 외삽한 값으로, 40턴에서 실측의 3.4배였다.
  이력 절단은 비용을 더 낮추지만 성립 조건은 아니다.

- 그 밖에 미해결: Jetson 적용, 블라인드 평가로 선정한 목소리의 대체, 아동 원음의 국외
  전송.

### 7.3 정책과 법이 속도보다 먼저 제약한다

2026년 9월 11일 조사 결과, 전환의 실질적 제약은 성능이 아니라 약관과 법이다.

- **Gemini API는 사용할 수 없다.** 추가 서비스 약관이 18세 미만이 접근할 가능성이 있는
  애플리케이션에 서비스를 사용하지 않도록 규정한다. 7.1절에서 측정한 속도와 무료 사용
  한도는 고려 대상이 아니다. 유료 구간의 비용은 캐시가 없어 OpenAI보다 높다(7.2절).
- **OpenAI는 만 13세 미만의 개인정보 처리에 데이터 무보관(ZDR) 적용을 먼저 요구한다.**
  `/v1/realtime`은 ZDR 적용 대상이지만 사전 승인제이며 일반 종량제 계정에는 적용되지
  않는다. 기본 상태에서는 남용 감시 목적으로 30일간 보관된다. 한국 리전을 선택해도
  저장 위치만 국내이고 처리는 국외에서 이루어진다. 따라서 기관 명의의 ZDR 신청이
  선결 조건이다.
- **대학 연구 과제에는 개인정보 보호법이 적용된다**(6.4절).

### 7.4 로컬 파이프라인을 남기는 이유

위 제약에 따라 현행 로컬 파이프라인의 위치가 바뀐다. 문서화를 위해 고정한 과거의 구성이
아니라, **아이 음성을 외부로 보내지 않는 유일한 경로이자 연결 실패 시의 대비**다.

Moxie의 사례가 같은 방향을 가리킨다. 클라우드에 전적으로 의존한 아동용 대화 로봇으로,
2025년 1월 제조사 폐업과 함께 서버가 종료되어 판매된 기기 전체가 동작을 멈추었다.

실무적으로는 두 가지 중 하나를 선택해야 한다. 기관 명의로 ZDR을 신청하여 아동 음성을
API로 보내는 길과, 음성 처리는 로컬에 두고 텍스트만 API로 보내는 길이다. 후자는 7.1절의
이득 대부분을 포기하는 대신 법적 제약을 회피한다. 이 선택은 지도 교수의 판단 사항으로
남긴다.

## 8. 결론

### 8.1 목표 대비 결과

1.1절에서 세운 목표 세 가지에 대한 결과다.

| 목표 | 결과 | 근거 |
|---|---|---|
| 단일 보드에서 대화 루프를 동작시킨다 | **달성** — 다만 놀이 5종 중 2종, 비전·부모 브리핑 미구현 | 5.1, 2.3 |
| 체감 응답 지연 3초 이내 | **미달** — 중앙 4.14초, 3초 이내 0/5턴 | 5.1 |
| 안전 조건을 구조적으로 보장 | **부분 달성** — 프롬프트 규칙으로 위험 응답 15/28에서 0/42. 다만 런타임 가드 미적용, 자동 판정은 하한 | 3.9, 6.3 |

지연 목표 미달의 구조를 밝혀 두는 것이 결과 자체보다 중요하다. 4.14초의 구간별 중앙값은
무음 대기 1.12초, 인식 0.61초, 응답 생성 1.57초, 음성 합성 0.76초다(턴마다 긴 구간이
달라 합은 체감 중앙값과 일치하지 않는다 — 5.1절). 이 가운데 무음 대기는 판정
모델로 줄이려는 시도가 유아 음성에서 기각되었고(4.1절), 응답 생성은 89%가 서버 시간이어서
프롬프트나 모델 크기로 줄일 수 없다(5.2절). 즉 남은 수단이 구성 변경뿐이며, 그 측정이
7장의 전환 결정으로 이어졌다.

### 8.2 재사용 가치가 있는 산출물

이 프로젝트에서 재사용 가치가 가장 높은 산출물은 동작하는 시스템 자체보다 다음 세 가지다.

첫째, 성인 음성을 전제로 한 부품이 유아 음성에서 무너지는 정도를 같은 코드 경로에서
측정한 기록이다. 문장 종료점 검출의 97.8%(성인, 제공사 공개 데이터) 대 37.3%, 음성 인식의 문자 오류율
31.46%와
연령별 분해가 여기에 해당한다. 이 수치들은 유아 대상 음성 시스템을 설계하는 다른 작업에
그대로 인용될 수 있다.

둘째, 기각의 기록이다. 아홉 가지 선택지를 측정으로 배제하였고, 각각에 대해 측정 방법과
수치를 남겼다. 특히 프롬프트 축소, 문장 단위 합성 스트리밍, 오디오 기반 종료점 검출은
통상 효과가 있다고 전제되는 처방인데 이 시스템에서는 이득이 없음을 확인하였다.

셋째, 측정의 신뢰도를 스스로 점검한 기록이다. 측정 도구의 결함으로 결론이 뒤집힌 네 건을
그대로 남겼고, 그 과정에서 원본 자료로 돌아가 확인하는 절차와 도구가 운영 코드를
재구현하지 않는 규칙을 세웠다.

### 8.3 남은 과제

우선순위 순이다.

1. **대상 아동의 실사용 시험.** 이 보고서의 모든 실기 수치는 성인 발화로 얻은 것이다.
   2세 아동에서의 동작은 미확인이며, 시험하려면 기관생명윤리위원회 심의와 법정대리인
   동의가 선행되어야 한다(6.4절).
2. **스피커 확보와 음향 결합 계층 검증.** 재생 선행 여유값, 노래 재생 중의 호출어 검출,
   음향 반향이 모두 여기에 걸려 있다. 도구는 준비되어 있다.
3. **헛깨움을 목표 안으로.** 현재 시간당 1.33~2.67회로 목표(1회 이하)를 넘는다. 수 시간
   단위의 연속 측정과 임계값 재조정이 필요하다.
4. **안전 판정기의 런타임 연결.** 평가 지표로만 쓰이는 두 판정기를 응답 경로의 가드로
   붙인다. 프롬프트로 안전을 확보하는 방식이 용량 한계에 도달했으므로(3.9절) 우선순위가
   높다.
5. **아동 실음성으로 호출어 검출기 재평가.** 학습 데이터가 전부 합성음이므로, 합성음
   재현율과 실음성 재현율의 간격이 이 부품의 최대 미지수다.

## 부록 A. 실행 방법과 측정 도구

### A.1 실행

노트북과 Jetson 모두 conda 환경 `jaeha_bot`을 사용한다.

```bash
conda activate jaeha_bot && python -m app.main
```

마이크와 음성 합성 없이 대화와 놀이만 확인하려면 `--text`를 붙인다. 모듈 단독 실행도
가능하다 — `python -m app.wake`는 마이크 없이 문자열 판정만, `python -m app.education_modes`
는 언어모델 없이 놀이 상태머신만 확인한다.

Jetson 배포는 컨테이너가 아니라 SSH로 코드만 전송한다(Jetson은 실행 전용). Jetson 환경은
노트북과 다르다 — Python 3.10, 전용 pip 인덱스, ctranslate2와 llama-cpp는 CUDA 소스 빌드다.
`requirements.txt`로 그대로 설치하면 GPU가 잡히지 않는다.

```bash
bash push_code.sh                     # app/ configs/ scenarios/ data/ 전송
./run.sh check                        # 장치·모델·설정 점검
```

`configs/local.yaml`은 기계별 설정 덮어쓰기이므로 저장소에 포함하지 않는다. 노래 재생
기능은 기본 꺼짐이며 Jetson의 `local.yaml`에서만 활성화한다.

### A.2 측정 도구

모든 측정 도구는 운영 코드의 판정 경로를 그대로 호출한다. 판정 로직을 도구 안에서 다시
구현하지 않는 것이 이 프로젝트의 규칙이다(4.9절).

```bash
python tools/eval_llm.py --rescore reports/eval/eval_20260811_212824.json
```

원자료가 큰 두 실험은 요약만 저장소에 남기고 원자료는 도구로 재생성한다. 문장 종료점
채점은 발화 153개에 판정 3,060회를 기록하여 파일 하나가 2만 줄을 넘기 때문이고, 호출어
학습 데이터는 합성 음성 수만 건으로 수백 MB이기 때문이다. 재현 명령은 각
`reports/*/README.md`에 적어 두었다.
