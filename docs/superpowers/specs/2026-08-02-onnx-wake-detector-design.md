# ONNX 호출어 감지기 설계 (재하봇)

작성일: 2026-08-02
상태: 승인됨 (구현 계획 대기)

## 1. 목적

대기 중인 재하봇을 유아가 **"재하봇"이라고 불러서** 스스로 깨우게 한다.

현재 감지기는 STT 텍스트를 '재하봇'과 자모 유사도로 비교하는 방식인데, 실측 결과
구조적 한계가 확인되어 `wake.enabled: false`로 꺼 둔 상태다:

- **인식이 빡빡함** — '재하봇'은 whisper 학습에 없는 고유명사(OOV)라 발음대로 뭉개진다.
  수집한 28개 샘플에서 또박또박 발음은 잡히지만 웅얼거림은 STT가 아예 딴판으로 출력한다
  (제 앞서어 / 제가 웃어 / 차보 / 제아버지). 매칭으로 복구 불가.
- **받아쓰는 동안 놓침** — 대기 중에도 whisper를 돌리므로, 받아쓰기하는 4~6초 사이에
  부르면 그 호출을 통째로 놓친다.

전용 KWS(keyword spotting) 모델은 받아쓰기를 하지 않고 **음향 패턴만** 감지하므로
두 문제가 모두 사라진다. 학습은 Colab에서 `livekit-wakeword`로 진행 중이고,
이 문서는 **젯슨에서 그 결과물(ONNX)을 돌리는 쪽**을 설계한다.

## 2. 제약조건

| 제약 | 내용 | 출처 |
|---|---|---|
| 단일 오디오 장치 | 젯슨 ReSpeaker는 hw:0,0 하나뿐이라 `InputStream`을 둘 동시에 못 연다 | 하드웨어 |
| Python 3.10 | `livekit-wakeword` 패키지는 **Python ≥3.11 요구** → 젯슨 설치 불가 | 실기 확인 (3.10.20) |
| 메모리 8GB | STT·LLM·TTS가 이미 상주. 감지기는 가벼워야 함 | 하드웨어 |

**Python 3.10 제약의 해결:** 학습(Colab, py3.11+)과 추론(젯슨)을 분리한다.
추론에 필요한 건 **ONNX 파일 3개뿐**이고, 젯슨엔 이미 실행 환경이 갖춰져 있다:

```
onnxruntime 1.24.0  (TensorRT / CUDA / CPU 프로바이더)
numpy 2.2.6
```

Supertonic TTS가 이미 onnxruntime을 쓰고 있어 **새 의존성이 0개**다.
젯슨 환경(py3.10)을 건드리지 않으므로 STT·LLM·TTS에 영향이 없다.

## 3. 전처리 체인

openWakeWord 원본 구현에서 확인한 정확한 흐름이다 (livekit-wakeword는 openWakeWord 기반이라 호환).

```
80ms 프레임 (1280샘플, int16, 16kHz)
   │
   ▼ melspectrogram.onnx
멜 8프레임  ──[정규화: x/10 + 2]──►  멜 링버퍼 (최근 76프레임)
   │
   ▼ embedding_model.onnx   (창 76프레임, 보폭 8프레임)
임베딩 1개 (96차원)  ──►  임베딩 링버퍼 (최근 16개)
   │
   ▼ jaehabot.onnx
score (0~1)
```

**1280샘플 = 멜 8프레임 = 보폭 정확히 1칸** → 프레임 하나당 임베딩이 정확히 하나 생긴다.

### 텐서 계약

| 모델 | 입력 | 출력 |
|---|---|---|
| `melspectrogram.onnx` | 원시 오디오 `(1, 1280)` | 멜 |
| `embedding_model.onnx` | 멜 `(76, 32, 1)` | 임베딩 `(1, 1, 1, 96)` |
| `jaehabot.onnx` | `embeddings (1, 16, 96)` float32 | `score (1, 1)` float32, opset 18 |

### ⚠️ 조용한 실패 지점

**멜 출력에 `x/10 + 2` 정규화를 반드시 적용해야 한다.**
빠뜨려도 예외가 나지 않고 점수만 무의미해진다. 그러면 "모델이 나쁜 건가, 코드가 틀린 건가"를
구분할 수 없어 디버깅이 매우 어려워진다. 구현 시 최우선 검증 항목.

## 4. 구조

### 4.1 오디오 소비 방식 — 스트리밍 증분

프레임을 80ms씩 읽어 임베딩을 **하나씩 증분 생성**한다. 2초 윈도우를 매번 통째로
재계산하는 대안도 있으나 채택하지 않았다:

- 분류기는 **증분 방식으로 만들어진 임베딩으로 학습**된다. 다른 방식으로 입력을 구성하면
  경계 처리 차이로 점수가 어긋날 수 있고, 그때 **모델 문제인지 입력 문제인지 구분이 안 된다.**
- 우리의 1순위 실패 유형이 "불렀는데 안 깨어남"(STT 방식에서 20번 중 12번만 성공)이므로,
  감지율에 불확실성을 더하는 선택을 피한다.
- 증분 방식의 추가 비용은 링버퍼 두 개뿐이다.

**VAD로 게이팅하는 방안은 명시적으로 기각한다.** 소리가 있을 때만 추론해 CPU를 아끼는
방식은 그럴듯하지만, 이미 같은 유형의 버그를 겪었다 — `min_start_rms`가 높아 작은 발화가
문턱을 못 넘어 "입력 없음"이 됐던 문제. 유아 목소리는 작아서 VAD 문턱을 못 넘으면
**감지기까지 도달조차 못 한다.** 대기 중엔 STT·LLM·TTS가 모두 멈춰 있어 CPU 여유가
충분하므로, 아끼는 이득보다 놓칠 위험이 크다.

### 4.2 단일 스트림 공유 + 프리롤

상용 스피커(Alexa 레퍼런스 설계)의 방식을 따른다: **마이크 스트림을 닫지 않는다.**

```
sd.InputStream  (한 번 열고 유지)
        │
        ├─ 프리롤 링버퍼 (최근 0.5초)
        │
        ├─[대기]→ OnnxWakeDetector      : 80ms씩 읽어 점수 판정
        │
        └─[대화]→ record_until_silence  : 프리롤로 시작해 이어서 녹음
```

감지 후 스트림을 닫고 STT가 새로 여는 구조는 채택하지 않는다. 그러면
**ALSA 재오픈 + 소음 바닥 재측정(0.3초) + 에코 쿨다운(0.3초) = 최소 0.7초의 "귀 먹은 구간"**이
아이가 말을 시작하는 바로 그 순간에 생긴다. 스트림을 유지하면 이 구간이 사라지고,
단일 장치 제약과도 더 잘 맞는다(스트림이 애초에 하나뿐이라 충돌 여지가 없음).

**프리롤 = 0.5초.** 감지는 호출어가 끝난 직후에 걸리므로 감지 지연을 덮을 만큼이면 충분하고,
Alexa가 쓰는 값(16kHz에서 8000샘플)과 같다. 더 길게 잡으면 호출 직전의 TV 소리나
부모 말소리를 끌어들이는데, whisper는 그런 입력에서 환각을 일으켜 폭주한 전력이 있다
(`_trim_edges`가 무음은 잘라내지만 타인의 말소리는 못 거른다).

### 4.3 인사말 분기

호출어 감지 직후 **0.5초 동안 에너지를 관찰**해 두 패턴을 자동으로 가른다:

| 아이가 한 말 | 판단 | 동작 |
|---|---|---|
| "재하봇!" *(멈춤)* | 부르고 기다리기 | 프리롤 폐기 → **인사 후 새로 듣기** |
| "재하봇 이거 뭐야?" *(한 숨)* | 한 숨 패턴 | **인사 생략** → 프리롤+이어지는 음성을 바로 STT로 |

2세 아이는 거의 항상 전자라 인사말 피드백을 받고, 형제나 부모가 한 숨에 말하면
후자로 자동 처리된다. 아이가 뭘 고를 필요도, 별도 설정도 없다.

분기 없이 항상 인사하면 프리롤이 **무의미해진다** — 인사에 1~2초가 걸려 프리롤이 낡고,
그걸 STT에 넣으면 호출어 자체를 요청으로 착각한다.

### 4.4 세션 동작 (기존 유지, 변경 없음)

호출어는 **잠들어 있을 때 깨우는 용도**일 뿐이다. 한 번 깨면 대화가 열려 있고
매 발화마다 다시 부를 필요가 없다:

```
아이: "재하봇!"       → 깨어남
봇:   "응! 왜 불렀어?"
아이: "이거 뭐야?"     ← 호출어 불필요
아이: "동물 놀이 하자"  ← 호출어 불필요
   ⋮
(30초 무음) 또는 "잘 자" → 다시 대기
```

이 상태머신은 이미 구현·젯슨 검증 완료다. 이번 작업은 **감지기만 교체**한다.

## 5. 컴포넌트

두 감지기는 **입력 자체가 다르다** (STT는 텍스트, ONNX는 오디오). 따라서
`is_wake_word(text)` 수준에서는 교체가 불가능하고, 경계를 **"깨어날 때까지 기다린다"**
수준으로 올려야 한다.

```python
class WakeResult:
    preroll: np.ndarray   # 감지 시점 직전 0.5초 오디오 (float32, 16kHz)
    continued: bool       # 감지 직후에도 말이 이어졌는가 (인사말 분기용)

class WakeDetector:
    def wait_for_wake(self) -> WakeResult | None
    # None = 타임아웃(안 깨움) / WakeResult = 깨움
```

`SttWakeDetector`는 오디오를 다루지 않으므로 `preroll`을 빈 배열, `continued`를
`False`로 채운다 — 항상 인사말 분기의 "부르고 기다리기" 쪽으로 가며, 이는 STT 방식의
기존 동작과 같다.

| 파일 | 상태 | 역할 |
|---|---|---|
| `app/audio_source.py` | **신규** | 단일 `InputStream` 소유, 프레임 공급, 프리롤 링버퍼, 소음 바닥 1회 측정 |
| `app/wake_onnx.py` | **신규** | `OnnxWakeDetector` — 3단 체인, 링버퍼 2개, 점수 판정, 인사말 분기 |
| `app/wake.py` | 유지 + 래핑 | 기존 자모 판정을 `SttWakeDetector`로 감싸 인터페이스 통일 |
| `app/stt_module.py` | 인자 추가 | `record_until_silence(source=None)` — 넘기면 공유 소스, 없으면 기존처럼 자체 스트림 |
| `app/main.py` | 단순화 | 대기 분기가 `detector.wait_for_wake()` 한 줄로 축소 |
| `models/wake/` | **신규** | `melspectrogram.onnx`, `embedding_model.onnx`, `jaehabot.onnx` |

`stt_module`의 `source` 기본값을 `None`으로 두면 기존 호출부(`_repl`, 스크래치패드
검증 스크립트들)가 그대로 동작한다 — 검증 끝난 코드를 깨뜨리지 않는다.

## 6. 설정

```yaml
wake:
  enabled: true
  detector: onnx          # onnx | stt  ← 모델이 부족하면 한 줄로 롤백
  onnx:
    model_dir: models/wake
    classifier: jaehabot.onnx
    threshold: 0.5        # 실기 측정 후 확정
    trigger_frames: 2     # 점수가 threshold 이상인 프레임이 연속 2개 '이상'이어야 깨움
                          # (단발 점수 튐으로 인한 오탐 억제)
    preroll: 0.5          # 초. 실기서 잘리면 올림
    providers: [CPUExecutionProvider]
  sleep_timeout: 30       # (기존)
```

젯슨에 TensorRT·CUDA 프로바이더가 있지만 **CPU를 기본으로 한다.** 모델이 수백 KB라
CPU로 충분하고, GPU는 LLM에 양보하는 편이 낫다.

## 7. 에러 처리

| 상황 | 동작 |
|---|---|
| ONNX 파일 없음 / 로드 실패 | 경고 로그 후 **STT 감지기로 자동 폴백**. 모델을 아직 안 넣었어도 봇이 죽지 않는다 |
| 마이크 없음 | 기존 `_setup_audio_device()` 폴백 재사용 (검증 완료된 경로) |
| 점수 진단 | 일정 주기로 **최근 최고 점수**를 로그에 남긴다. 임계값을 실측으로 정하는 근거 |

진단 로그는 STT 방식에서 `[대기] 안 깨움 (거리 X)`가 임계값 튜닝에 유용했던 경험을 따른다.

## 8. 테스트

모델 도착 전에 할 수 있는 것부터 배치한다.

| # | 검증 | 모델 필요? | 마이크 필요? |
|---|---|---|---|
| 1 | 체인 형상 — 더미 오디오가 `(1,1280)→멜→(1,16,96)→(1,1)`로 흐르는지 | 아니오 (melspec·embedding만) | 아니오 |
| 2 | 정규화 — `x/10 + 2` 적용 여부를 원본 값과 비교 | 아니오 | 아니오 |
| 3 | 링버퍼 — 프레임 N개 투입 시 임베딩 N개 생성, 16칸 유지 | 아니오 | 아니오 |
| 4 | 폴백 — 분류기 파일이 없을 때 STT 감지기로 넘어가는지 | 아니오 | 아니오 |
| 5 | 프리롤 — 감지 시점 이전 0.5초가 보존되는지 | 아니오 | 아니오 (합성 신호) |
| 6 | 인사말 분기 — 연속 발화/무음 두 경우가 갈리는지 | 아니오 | 아니오 (합성 신호) |
| 7 | **실기** — 또박또박 / 웅얼거림 / 무관한 말의 점수 분포 → 임계값 확정 | 예 | 예 |
| 8 | **실기** — 한 숨 패턴에서 뒷말이 안 잘리는지 | 예 | 예 |

1~6번은 **지금 바로** 할 수 있고, 학습이 끝나면 7~8번만 하면 된다.

## 9. 완료 기준

- [ ] 대기 중 "재하봇"을 부르면 깨어난다 (유아 웅얼거림 포함, 목표 감지율은 7번 실측 후 확정)
- [ ] 무관한 말·생활 소음에 오작동하지 않는다

- [ ] `wake.detector: stt` 한 줄로 이전 방식으로 되돌아간다

## 10. 범위 밖

- **대화 중 끼어들기(barge-in)** — 봇이 말하는 중에 호출해 끊는 기능. 에코 처리(AEC 또는
  TTS 구간 무시)가 추가로 필요하고, 현재 코드는 half-duplex(`ECHO_COOLDOWN`) 전제다.
  감지기를 분리해 두므로 나중에 확장 가능.
- **모델 학습 자체** — Colab에서 별도 진행 중.
- **STT 지연 개선** — 젯슨 CPU ct2의 기본 4~6초는 별도 과제(GPU화).
