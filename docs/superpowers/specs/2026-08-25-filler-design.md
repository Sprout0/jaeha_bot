# 필러(맞장구) 즉시 재생 — 설계

**날짜** 2026-08-25
**목적** 아이가 말을 끝낸 뒤 첫 소리까지의 침묵을 4.17초 → 1.70초로 줄인다.

## 왜

젯슨 실측 체감 예산(08-20 + TRT 반영):

```
꼬리 1.20 + 인식 0.50 + 생각 1.75 + 첫소리 0.72 ≈ 4.17s
```

남은 실지연 레버(꼬리 축소 -0.30s, 문장 스트리밍 -0.2~0.3s)를 전부 써도 3.6초대다.
**3초 목표는 실지연만으로는 안 된다.**

필러는 실지연을 줄이지 않는다. **진짜 답이 나오는 시각은 1ms도 안 바뀐다.**
바뀌는 것은 아이가 처음 소리를 듣는 시각뿐이다.

```
지금        아이 말 끝 ├──────── 4.17초 침묵 ────────┤ "그건 말이야…"
필러 넣으면  아이 말 끝 ├─1.70s─┤"음~"├── 2.47초 ──┤ "그건 말이야…"
```

즉 이것은 파이프라인 최적화가 아니라 **체감 설계**다. 실지연 레버와 서로 겹치지 않으므로
같이 적용한다.

🔴 **가장 큰 값어치는 재발화 차단이다.** 침묵이 길면 아이는 "티드?" 하고 다시 부르는데,
그 시점엔 `listen()`이 이미 끝나 봇이 안 듣고 있고 `source.drain()`이 쓸어낸다.
**아이가 다시 말한 것이 통째로 사라진다.** 빠른 맞장구가 이걸 막는다.

## 범위

- 자유대화(LLM) 턴에만 적용한다.
  ⚠️ 처음 쓴 근거 "놀이 턴은 상태머신이 즉답(총 2.4초)"은 **틀렸다**(2026-08-26 정정).
  `GameManager(render=agent.render)` 라 `_voice()` 가 LLM 을 부른다 — 젯슨 실측
  `kind=game_start` 생각 **1.47초**다. 놀이 턴에도 침묵은 똑같이 있다.
  ➡️ 그래도 안 내는 진짜 이유: **놀이 턴의 답 자체가 맞장구다.**
     "좋아! 고양이는 야옹?" / "잘했어! 더 할래?" / "재밌었어! 또 놀자!"
     앞에 "음…"을 붙이면 맞장구가 두 번 나간다. 게다가 `await_quiet` 이 생긴 뒤로는
     답이 필러를 기다리므로 **놀이 턴을 실제로 느리게 만든다.**
- 짧은 맞장구 **하나**만 낸다. 답이 나올 때까지 이어 붙이지 않는다.
- 침묵이 `1.70s + 2.47s` 두 덩어리로 쪼개지는 것은 **의도한 트레이드오프**다.
  실기에서 두 번째 공백이 더 어색하면 이어 붙이기 안으로 옮긴다.

## 구조

새 모듈 `app/filler.py`.

```
FillerBank
 ├ ensure(tts)   캐시에 없거나 목소리가 바뀌었으면 합성해 저장
 ├ next()        직전과 다른 필러 하나
 └ play(sink)    논블로킹 재생. 실패해도 예외를 위로 안 던진다
```

### `audio_assets.yaml`에 넣지 않는 이유 🔴

그 파일의 `playable()`/`titles()`는 **LLM 툴 스키마의 enum으로 그대로 쓰인다**
(`app/audio_player.py` 상단 주석). 필러를 거기 등록하면 봇이 *"음~ 틀어줄게"*라고
말할 수 있게 되고, 현재활동 날조를 구조로 막아 둔 장치가 깨진다.

→ 설정은 `configs/model_paths.yaml`의 `filler:` 섹션 신설.

### 캐시

- 위치 `~/.cache/jaeha_filler/` (TRT 캐시와 같은 방식, git 미추적, 기계별)
- 키 = **목소리 + speed + total_steps + 문구**
  하나라도 바뀌면 자동으로 다시 만든다. F2에서 다른 목소리로 갈아탔을 때
  **필러만 옛 목소리로 겉도는 사고를 구조로 막는다.**
- 생성은 `main.preload()`에서. 문구 6개 × 약 0.45초 ≈ 2.7초, 기동 1회뿐이고
  이미 TRT 엔진 빌드로 +8.0초를 쓰고 있어 체감 차이가 없다.

## 언제 나가는가

`app/main.py`, **놀이 판정 뒤 / LLM 호출 직전**:

```python
reply, kind = games.handle(text), "game"
if reply is None:
    reply, kind = games.maybe_start(text), "game_start"
if reply is None:
    filler.play()                                  # ← 여기
    reply, kind = agent.respond(text)["text"], "llm"
```

- 놀이 **판정**(match_trigger)은 순수 상태머신이라 마이크로초다. 여기 두어도 지연이 안 붙는다.
  (판정은 빠르지만 놀이 **응답 생성**은 LLM 을 탄다 — 위 정정 참고.)
- `text`가 비면 위에서 이미 `continue` 한다 → **아무 말 안 한 아이에게 "음~" 하는 일이
  구조적으로 없다.**

### 왜 '말하기 1초 전'이 아니라 즉시인가

늦게 넣자는 안(답 1초 전 ≈ 3.0초 지점)을 검토했고 기각했다.

1. **답이 언제 올지 모른다.** 생각이 중앙 1.75s·p90 2.18s로 흔들리고 합성은 답 길이를
   따른다. 예측이 빗나가 늦게 터지면 **봇이 제 답 위에 겹쳐 말한다** — 지금 침묵보다 나쁘다.
2. **늦은 맞장구는 맞장구가 아니다.** 3.0초면 아이는 이미 "안 들었나?"를 다 겪은 뒤고
   0.8초 뒤엔 진짜 답이 온다. 이득이 -2.47s → -1.17s로 반토막.
3. **재발화 차단(위 🔴)이 필러의 진짜 값어치인데, 그건 빠를수록 이긴다.**

→ 기본 `delay_s: 0.0`(즉시). 다만 **설정값으로 뺀다** — 젯슨에서 들어보고 코드 수정 없이
   0.5초든 1.0초든 밀 수 있어야 한다.

## 소리가 안 겹치게

`sd.play`는 전역 스트림 하나를 공유해 두 번째 재생이 첫 번째를 끊는다
(`SoundDeviceSink.play`, `TTSModule.speak` 둘 다 `sd.play`를 쓴다).
여기서는 이게 유리하다 — 진짜 답이 시작되면 필러가 알아서 끊긴다.
필러 0.3~0.5초 vs 남은 대기 2.47초라 실제로는 거의 항상 이미 끝나 있다.

🔴 **필러 wav에는 앞 무음 `PLAY_PAD_S`(0.15초)를 구워 넣는다.**
`SoundDeviceSink`는 `TTSModule`과 달리 패딩을 안 붙이는데, sounddevice 스트림 시작이
앞 샘플을 흘리므로 안 하면 **첫 음절이 잘린다.** TTSModule이 이미 겪고 고친 문제다.

## 실패해도 대화는 산다

필러는 기능이 아니라 최적화다. 합성 실패·파일 없음·장치 없음·재생 실패는
로그만 남기고 넘어간다. **예외를 위로 절대 안 던진다.**

## 문구

```
음~ / 그래? / 아~ / 오~ / 어~ / 응, 응
```

같은 소리가 연속으로 나오지 않게 직전 것을 기억해 피한다.

## 검증 (하드웨어 없이)

- 직전과 같은 필러를 연속으로 안 낸다
- 목소리·speed·total_steps가 바뀌면 캐시를 무효화한다
- 캐시가 있으면 합성을 다시 안 부른다
- 생성된 오디오 앞에 0.15초 무음이 있다
- 놀이 턴엔 안 나가고 LLM 턴엔 나간다
- **합성이 예외를 던져도 답변은 정상으로 나간다**
- `delay_s`가 0보다 크면 그만큼 미뤄 재생한다

`metrics`에 필러 발동 여부·시각을 남겨 젯슨에서 체감 변화를 숫자로 확인한다.
