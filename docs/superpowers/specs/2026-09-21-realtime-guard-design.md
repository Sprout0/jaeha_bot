# 전면 API 봇 — 안전 막기 · 정정 · 끊김 복구 설계 (2026-09-21)

> 대상: 전면 API 봇(`app/main_realtime.py`). 로컬 봇(`app/main.py`)은 건드리지 않는다.
> 앞선 설계: `2026-09-16-realtime-pipeline-design.md` (그때 안전은 "B: 로그만"으로 두었다).

## 1. 범위

| 넣는 것 | 빼는 것 |
|---|---|
| 위험한 답을 **소리가 나가기 전에** 막고 안전 문장으로 바꾸기 | 비용 상한(사용자 결정: 이번엔 제외) |
| 못 하는 걸 하겠다는 답을 **바로 정정**하기 | 텔레그램 전송(자리만 만들고 보내지 않는다) |
| 연결이 끊기면 **조용히 다시 붙어** 이어가기 | 로컬 STT·TTS 폴백 (09-16 결정 A 로 뺐다) |
| 막은 일·정정한 일·복구 실패를 **부모 기록**으로 남기기 | 소리 녹음 저장 |

## 2. 확정한 결정

| 항목 | 결정 | 근거 |
|---|---|---|
| 막은 뒤 | 안전 문장 + 부모 기록 | 사용자 선택. 2세는 스스로 판단 못 하니 어른에게 보낸다(`safety.py` 머리말) |
| 소리 붙잡기 | **위험 신호가 있는 턴만** | 평소 대화 속도 유지. 안 붙잡으면 위험한 말 앞 0.2~0.5초가 새어 나간다 |
| 끊김 | 조용히 다시 붙고 이어가기 | 지금은 아이가 다시 불러야 한다 |
| 부모 기록 전달 | 파일 + `notify()` 자리. 텔레그램은 나중 | 사용자 결정. 기기 밖으로 나가는 내용은 그때 정한다 |
| 못 하는 것 | 끊지 않고 **말 뒤에 정정** | 위험이 아니라 거짓말이다. 끊는 것보다 정정이 덜 이상하다 |

## 3. 구성

### 새 파일
| 파일 | 하는 일 | 모르는 것 |
|---|---|---|
| `app/reply_gate.py` | 이 턴을 붙잡을지, 글자가 올 때마다 문제가 있는지, 끝났을 때 내보낼지/막을지/정정할지 판단 | 소리·소켓·시계(시각은 인자로 받는다) |
| `app/guardian_log.py` | 부모 기록을 `logs/guardian_YYYYMMDD.jsonl` 에 남기고 `notify()` 로 넘긴다. 기본 notifier 는 아무것도 안 한다 | 대화 흐름 |

### 바꾸는 파일
| 파일 | 바뀌는 것 |
|---|---|
| `app/realtime_conversation.py` | 소리 조각을 게이트 결정에 따라 스피커 또는 보류 버퍼로. 취소·안전 문장·정정 연결. 연결 대신 **연결을 만드는 함수**를 받아 다시 붙기 |
| `app/realtime_turn.py` | `PHRASES` 에 `safe`, `cant` 추가(설정 문장으로 덮어쓸 수 있게) |
| `app/main_realtime.py` | 설정 읽기, 연결 함수·부모 기록 넘기기, 고정 문구 캐시에 새 문장 포함 |
| `app/metrics.py` | `record_realtime_turn` 에 `held`, `hold_s`, `blocked`, `corrected`, `reconnects` |
| `configs/model_paths.yaml` | `realtime.guard` 블록 |

가져다 쓰는 것(수정 없음): `app/safety.py`(`check_reply`, `danger_words`), `app/claims.py`(`find_fabrications`), `configs/safety_rules.yaml`.

## 4. 위험 신호 — 언제 붙잡는가

아이 말을 받아 적은 직후(`_on_transcript`) 판단한다. 어휘는 `configs/safety_rules.yaml` 의 `reply_check.danger` 를 그대로 쓴다(코드에 박지 않는다).

- 아이 말에 **위험 낱말**(칼·가위·불·약·콘센트·창문·베란다·혼자 나가·낯선 사람 …)이 있으면 붙잡는다.
- **지시대명사(이거·저거·그거) + 먹기**(먹·맛·마셔)가 함께 있으면 붙잡는다 — 08-12 "이거 무슨 맛이야?" 사례.
- 그 밖에는 붙잡지 않는다.
- 노래 안내·놀이 템플릿처럼 **글자 그대로 읽는 턴**(`say_exactly`)은 붙잡지 않는다 — 우리가 쓴 문장이다.

## 5. 한 턴의 흐름

### 붙잡는 턴 (`hold`)
1. 소리 조각을 스피커 대신 보류 버퍼에 모은다. 글자는 계속 모은다.
2. `response.done` 이 오면 `safety.check_reply(글자, child_text=아이 말)` 로 검사한다.
   - 문제없음 → 보류 버퍼를 스피커로 한꺼번에 낸다.
   - 걸림 → 버퍼를 버리고 **안전 문장**(캐시 wav)을 낸다. 부모 기록 `safety_block`.
   - `빈응답` 판정은 막는 이유로 쓰지 않는다(막을 말이 없다). 로그에만 남긴다.
3. **한도:** 붙잡기 시작부터 `hold_cap_s`(3.0초) 안에 `done` 이 안 오면, 거기까지의 글자를 검사한다.
   - 문제없음 → 버퍼를 내보내고 그 뒤로는 흘려보내기(stream) 턴으로 바뀐다.
   - 걸림 → `response.cancel`, 버퍼를 버리고 안전 문장.

### 흘려보내는 턴 (`stream`, 기본)
1. 지금처럼 소리 조각을 바로 스피커로 낸다.
2. 글자 조각이 올 때마다 **지금까지의 글자**를 검사한다.
   - 걸림 → `response.cancel`, 스피커 대기열 비우기(`speaker.clear()`), 안전 문장. 부모 기록 `safety_block`(`leaked: true` — 앞부분이 나갔다).
3. ⚠️ 글자 도중 검사는 **위험행동제안** 같은 조합형 판정만 의미가 있다. "어른유도없음"은 문장 끝까지 봐야 알 수 있으므로 도중 검사에서는 쓰지 않고 `done` 에서만 본다. `done` 에서 걸리면 이미 다 나간 뒤이므로 부모 기록만 남기고 대체 문장은 말하지 않는다.

### 못 하는 것 (모든 자유대화·놀이 턴)
- `done` 에서 `claims.find_fabrications(글자)` 가 있으면, 답이 다 나간 뒤 **정정 문장**(캐시 wav)을 이어서 낸다. 부모 기록 `fabrication`.
- 안전으로 막힌 턴에는 정정을 붙이지 않는다(안전 문장이 이미 대신했다).

### 대화 기록(history)
- 막힌 턴은 모델이 한 말 대신 **안전 문장**을 기록한다 — 다음 턴에 모델이 막힌 답을 이어가지 않게.
- 정정된 턴은 모델의 답 뒤에 정정 문장을 붙여 기록한다.

## 6. 끊김 복구

- `Conversation` 은 `session` 대신 `make_session()`(새 `RealtimeSession` 을 돌려주는 함수)을 받는다.
- 대화 도중 `ConnectionLost` 가 나면:
  1. 말없이 새 연결을 연다. 간격 0.5 → 1 → 2초, 최대 `reconnect_tries`(3)번.
  2. 열리면 프롬프트와 **최근 대화 기록**을 다시 넣는다(`session.open(instructions, history)` 가 이미 한다).
  3. **답하던 중이었다면**(보류 중인 턴이 있었다면) 아이 말을 글자 메시지로 넣고 같은 방식(`respond` / 놀이 지시 / `say_exactly`)으로 답을 다시 요청한다. 반쯤 나간 소리는 스피커에서 비운다.
  4. 다시 붙는 동안 마이크 소리는 버린다(보낼 곳이 없다).
- 전부 실패하면 지금처럼 `lost` 문구를 말하고 대기로 간다. 부모 기록 `connection_lost`.
- 호출 직후 **첫 연결**이 실패할 때도 같은 재시도를 한다.

## 7. 부모 기록

`logs/guardian_YYYYMMDD.jsonl`, 한 줄에 하나:

```json
{"ts": "2026-09-21T10:12:03", "kind": "safety_block", "child": "칼 어딨어?",
 "reply": "칼은 부엌에 있어! 같이 찾아볼까?", "flags": ["위험행동제안"], "held": true, "leaked": false}
```

- `kind`: `safety_block` | `fabrication` | `connection_lost`
- **소리는 남기지 않는다.** 글자만.
- `GuardianLog(dir, notifier=None)` 에 `record(kind, **fields)` 를 둔다. 파일에 쓴 뒤 `notifier.notify(event)` 를 부른다.
  - 기본 notifier 는 아무것도 안 한다.
  - 텔레그램은 나중에 이 자리에 끼운다. 무엇을 내보낼지(원문/요약)는 그때 정한다.
- 기록·전송이 실패해도 대화는 멈추지 않는다(경고 로그만).

## 8. 설정

```yaml
realtime:
  guard:
    hold_on_risk: true
    hold_cap_s: 3.0
    reconnect_tries: 3
    safe_line: "그건 위험해! 엄마 아빠한테 같이 가자."
    cant_line: "아, 그건 아직 못 해. 대신 동물 소리 놀이 할까?"
```

- 두 문장은 기동 때 고정 문구 캐시로 미리 만든다(`VoiceCache`). 문장을 바꾸면 키가 바뀌어 다시 만든다.
- `hold_on_risk: false` 면 모든 턴이 흘려보내기(도중 검사·정정·복구는 그대로).

## 9. 오류 처리

| 상황 | 동작 |
|---|---|
| 안전 문장 캐시가 없다 | 경고 후 소리 없이 넘어간다(막는 것은 그대로 — 위험한 말은 안 나간다) |
| `response.cancel` 보내기 실패(끊김) | 끊김 복구로 넘어간다. 보류 버퍼는 버린다 |
| 판정기 예외 | 경고 로그. 붙잡는 턴이면 **내보내지 않고** 안전 문장(안전 쪽으로 실패) / 흘려보내는 턴이면 그대로 |
| 부모 기록 쓰기 실패 | 경고 로그만 |

## 10. 시험

### 자동 (소리·서버 없음, 가짜 연결)
- `reply_gate`: 위험 신호 판정(낱말·지시대명사+먹기·해당 없음·글자 그대로 턴), 붙잡기 결정, 도중 검사, 한도 초과 시 전환, done 판정(통과/막기/정정).
- `guardian_log`: 한 줄 형식, notifier 호출, 실패해도 예외 안 던짐.
- `Conversation`:
  - 붙잡은 턴이 문제없으면 `done` 뒤에 소리가 스피커로 나간다(그 전에는 안 나간다)
  - 붙잡은 턴이 걸리면 소리는 안 나가고 안전 문장이 나가며 부모 기록이 남는다
  - 흘려보내는 턴이 도중에 걸리면 `response.cancel` 이 가고 스피커가 비워진다
  - 못 하는 것이면 답 뒤에 정정 문장
  - 한도(3초) 초과 시 검사 후 내보내고 흘려보내기로 바뀐다
  - 끊겼다가 다시 붙고, 답하던 아이 말을 다시 요청한다 / 3번 다 실패하면 `lost`
  - 막힌 턴의 history 에는 안전 문장이 들어간다
- `metrics`: 새 필드가 기록된다.

### 젯슨 실기
1. "칼 어딨어?", "이거 먹어도 돼?" → 로그에 붙잡기, `hold_s` 로 느려진 정도 확인
2. 평소 말 → 붙잡지 않고 속도가 전과 같은지(`perceived_s`)
3. "색칠 놀이 하자" → 정정 문장이 붙는지
4. 대화 도중 공유기 선을 잠깐 뽑았다 꽂기 → 말없이 이어지는지, 오래 뽑으면 `lost` 로 가는지
5. `logs/guardian_날짜.jsonl` 확인
