# TTS 문장 스트리밍 실측 — 2026-08-28 (젯슨)

`tools/measure_first_sentence.py`. **재생 없이 합성만** 잰다(소리 안 남).
입력은 오늘 gpt 가 실제로 낸 답 32개(`reports/eval/eval_20260828_145622.json`) —
손으로 만든 문장은 길이 분포가 운영과 달라 숫자가 안 옮겨간다.
문장 분리는 운영과 같은 `TTSModule._split_sentences`.

## 결론: **기각. 이득이 0.047초다.**

```
n=32(전부 2문장)   중앙     최소     최대
글자수             21.5      9       31
통짜 합성          0.480s   0.280s  0.618s
첫문장 합성        0.435s   0.415s  0.477s
➡️ 첫 소리 이득    +0.047s  -0.150s +0.185s
여유(끊김 위험)    +1.296s  +0.813s +1.938s   음수 0/32
```

- **첫 문장 합성이 0.415~0.477초로 거의 일정하다** — 고정 비용이 지배적이다.
  통짜도 0.480초라 쪼개도 차이가 안 난다.
- 다만 **길이 무관은 아니다**: 글자수 vs 통짜합성 상관 **r = 0.66**.
  31자짜리 긴 답에서는 이득이 0.185초까지 간다. 우리 답변 중앙(21자)에서 0.047초일 뿐이다.
- **끊김 위험은 없다** — 여유가 항상 +0.8초 이상(첫 문장 재생 동안 나머지를 다 만든다).
  다만 벌 게 없으니 의미가 없다.

⚠️ **08-28 오전에 "이득은 TTS 합성 0.79초를 쪼개는 데 있다"고 두 번 말한 것은 틀렸다.**
   0.79초(첫 소리)의 대부분이 길이와 무관한 고정 비용이라 쪼개도 안 줄어든다.
   ➡️ 첫 소리를 줄이려면 문장 분할이 아니라 **합성 자체**(스텝 수·모델)를 건드려야 한다.
      TRT@12 는 08-24 에 튀는 소리로 기각됐으므로 남은 길이 좁다.

# few-shot 을 담는 그릇 — 2026-08-28 (노트북, 길이만 잰다)

`tools/bench_fewshot_form.py`. 결과: `reports/eval/fewshot_form_20260828.json`.
길이는 기계·회선과 무관하므로 노트북에서 재도 된다. 채점은 반드시 `spoken()` 을 거친
**아이가 실제로 듣는 문자열**로 한다.

## 물음

`_augment_system` 은 few-shot 18쌍을 시스템 프롬프트 안의 텍스트 줄로 넣는다:

    좋은 답변 예시(이 말투·길이를 따라해):
    - 아이가 "졸려요" 하면 -> "졸리구나! 코 자는 흉내 내볼까?"

모델 입장에선 **'예시를 설명하는 문장'이지 자기가 그렇게 말한 기록이 아니다.**
gpt 는 그래도 따르는데 HCX 는 안 따른다. 진짜 user/assistant 메시지쌍으로 넣으면?
⚠️ 두 팔이 보는 **예시 내용은 완전히 같다.** 다른 건 담는 그릇 하나뿐이다.

## 결과: **그릇을 바꾸니 HCX 의 꼬리가 gpt 수준으로 잡혔다**

```
팔                    중앙   평균   최대   30자초과
HCX-005/text         25.0   27.6    68    8/32  (25%)   <- 현행
HCX-005/turns        22.0   22.6    47    2/32  ( 6%)   <- 진짜 메시지쌍
gpt-4o-mini/text     21.0   21.3    49    2/32  ( 6%)
gpt-4o-mini/turns    21.0   20.8    35    3/32  ( 9%)
```

폭주하던 문항이 그대로 내려왔다:

```
[비는 왜 와?]         68자 -> 29자  "비가 오면 식물들이 자라니까! 하늘에서 물이 내려와."
[아까 그거 또 하자]    50자 -> 23자  "뭔지 잘 모르겠지만, 다시 해볼까? 멍멍?"
[곰 세 마리 틀어줘]    52자 -> 21자  "아직 노래를 못 틀어. 같이 불러볼까?"
[강아지는 왜 멍멍 해?]  56자 -> 35자
[동물 이름 많이 알려줘]  68자 -> 47자   <- 아직 최악(나열 버릇)
```

- **gpt 는 손해가 없다** — 중앙 21.0 그대로, 최대는 49 -> 35자로 오히려 좋아졌다.
- 말하기 시간 환산(0.6 + 글자×0.148): HCX 4.30s -> **3.86s**, gpt 3.71s.
  격차가 0.59초 -> **0.15초**로 줄어든다.

## ⚠️ 아직 확인 안 된 것

- **이건 길이만 잰 값이다.** 젯슨에서 파이프라인 체감으로 재지 않았다 —
  위 '말하기 3.86s'는 실측이 아니라 환산이다.
- **말투는 여전히 다르다.** 길이는 잡혔지만 "아이 말을 따라 하고 한두 낱말"은
  아직 아니다("강아지는 자기만의 언어로 소통해!" — 2세 어휘가 아니다).
- **프롬프트 캐시**를 확인 안 했다. 현행 text 형식에서 gpt 는 31턴 캐시가 걸렸다.
  메시지쌍으로 바꾸면 접두가 여전히 고정이라 걸릴 것으로 보이나 **재봐야 한다.**
- 운영 `_augment_system` 은 **손대지 않았다.** 바꾸려면 두 모델 다 영향을 받으므로
  gpt 무해(위 표)를 근거로 판단이 필요하다.

# 🔴🔴 few-shot 그릇 재검토 — **08-28 의 결론이 뒤집혔다** (2026-08-31, 노트북)

`tools/bench_fewshot_leak.py`. 결과: `reports/eval/fewshot_leak_20260831.json`,
`reports/eval/fewshot_leak_local_20260831.json`.

## 무엇을 놓쳤나

08-28 에 "메시지쌍(turns)으로 주면 HCX 의 30자 초과가 25% -> 6%" 를 쟀다.
**그건 길이만 잰 것이다.** 그 형식을 예전에 버린 이유는 안 봤다 —
`app/agent.py` 주석과 메모리에 이렇게 적혀 있었다:

> 가짜 대화이력으로 주입하면 이전 예시의 '주제'가 실제 답에 샘
> (무의미 입력에 '빨간색 게임' confabulation). 텍스트 방식으로 해결.

## 재현 조건이 핵심이다

누수는 **말할 거리가 없는 입력**에서만 보인다 — 모델이 지어내야 하는 자리에서
눈앞의 예시를 집어 온다. 평범한 질문으로 재면 답할 거리가 이미 있어 **안 나타난다.**
그래서 입력은 무의미한 말 24개만 쓴다(앞 둘은 whisper 가 소음에 붙이는 실제 환각 문구).

## 결과: 두 모델 다 샌다

```
팔                     누수 답변
gpt-4o-mini/text        0/24
gpt-4o-mini/turns       3/24  (12.5%)
local(EXAONE)/text      2/24  ( 8%)
local(EXAONE)/turns     7/24  (29%)
```

⚠️ 처음 n=12 로 쟀을 땐 gpt 가 0/12 여서 "gpt 는 무해"로 읽었다. **표본이 작았던 것이다.**

새는 낱말이 거의 전부 **'딸기'** — few-shot 마지막 쌍이 그것이다(18번 "딸기 좋아하는구나!
딸기는 빨개!"). **최신성 효과**로 보인다: turns 에서는 마지막 예시가 아이 말 바로 앞에 와서
'방금 나눈 대화'로 읽힌다.

```
[오]      -> 오! 딸기가 빨갛구나!
[네네]    -> 네! 그럼 딸기 먹을래?
[아 진짜]  -> 아 진짜! 딸기 먹어볼까?
[그래서]   -> 그래서 딸기가 빨갛지! 빨갛게 보이는 거지?
```

## 다만 text 도 흠이 있다 (로컬 한정)

`local/text` 는 누수는 적지만 **아이가 아니라 운영자에게 말한다**:

```
[그거] -> 알겠습니다! 앞으로 아이와 즐겁게 소통하면서 안전하게 놀이를 이끌어갈게요.
[네네] -> 네, 알겠습니다! 티드로서 아이와 즐겁고 안전한 시간을 보내는 데 집중하겠습니다.
```

24개 중 6~7개가 존댓말·어른말이다. turns 쪽은 이 고장이 거의 없다.
**즉 로컬 폴백에서는 두 형식이 서로 다른 방식으로 고장난다.**
