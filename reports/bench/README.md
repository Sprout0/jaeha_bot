`_augment_system` 은 few-shot 18쌍을 시스템 프롬프트 안의 텍스트 줄로 넣는다:

    좋은 답변 예시(이 말투·길이를 따라해):
    - 아이가 "졸려요" 하면 -> "졸리구나! 코 자는 흉내 내볼까?"

모델 입장에선 **'예시를 설명하는 문장'이지 자기가 그렇게 말한 기록이 아니다.**
gpt 는 그래도 따르는데 HCX 는 안 따른다. 진짜 user/assistant 메시지쌍으로 넣으면?
⚠️ 두 팔이 보는 **예시 내용은 완전히 같다.** 다른 건 담는 그릇 하나뿐이다.

## 결과: **그릇을 바꾸니 HCX 의 꼬리가 gpt 수준으로 잡혔다**

```
팔                    중앙   평균   최대   30자초과
HCX-005/text         25.0   27.6    68    8/32  (25%)   <- 현행
HCX-005/turns        22.0   22.6    47    2/32  ( 6%)   <- 진짜 메시지쌍

gpt-4o-mini/turns    21.0   20.8    35    3/32  ( 9%)
```

폭주하던 문항이 그대로 내려왔다:

```
[비는 왜 와?]         68자 -> 29자  "비가 오면 식물들이 자라니까! 하늘에서 물이 내려와."
[아까 그거 또 하자]    50자 -> 23자  "뭔지 잘 모르겠지만, 다시 해볼까? 멍멍?"
[곰 세 마리 틀어줘]    52자 -> 21자  "아직 노래를 못 틀어. 같이 불러볼까?"
[강아지는 왜 멍멍 해?]  56자 -> 35자
[동물 이름 많이 알려줘]  68자 -> 47자   <- 아직 최악(나열 버릇)
```

- **gpt 는 손해가 없다** — 중앙 21.0 그대로, 최대는 49 -> 35자로 오히려 좋아졌다.
- 말하기 시간 환산(0.6 + 글자×0.148): HCX 4.30s -> **3.86s**, gpt 3.71s.
  격차가 0.59초 -> **0.15초**로 줄어든다.

## ⚠️ 아직 확인 안 된 것

- **이건 길이만 잰 값이다.** 젯슨에서 파이프라인 체감으로 재지 않았다 —
  위 '말하기 3.86s'는 실측이 아니라 환산이다.
- **말투는 여전히 다르다.** 길이는 잡혔지만 "아이 말을 따라 하고 한두 낱말"은
  아직 아니다("강아지는 자기만의 언어로 소통해!" — 2세 어휘가 아니다).
- **프롬프트 캐시**를 확인 안 했다. 현행 text 형식에서 gpt 는 31턴 캐시가 걸렸다.
  메시지쌍으로 바꾸면 접두가 여전히 고정이라 걸릴 것으로 보이나 **재봐야 한다.**
- 운영 `_augment_system` 은 **손대지 않았다.** 바꾸려면 두 모델 다 영향을 받으므로
  gpt 무해(위 표)를 근거로 판단이 필요하다.

# 🔴 2026-09-02 '왕복'의 정체 — 네트워크가 아니라 **서버 시간**이다

08-28 분해가 말한 "생각의 89% 가 왕복"에서 그 왕복을 쪼갰다. 가설은 "openai SDK 의
`keepalive_expiry` 가 5초라, 턴 간격이 그보다 길어 **매 턴 새 연결을 연다**"였다.
연결은 실제로 매 턴 새로 열린다 — **그런데 그게 안 비싸다.**

⚠️ **잰 도구는 폐기했다**(사용자 결정, 2026-09-02). 결론만 남긴다. 다시 재려면:
소켓만 써서 DNS·TCP 연결·TLS 악수를 따로 잰 뒤(1층), 같은 바닥 질문을 스트림으로 쳐서
TTFT 를 본다(2층). 2층은 팔 셋 — `cold`(매번 새 클라이언트) · `reuse`(한 클라이언트,
기본 keepalive 5초) · `keepalive`(`http_client=httpx.Client(limits=httpx.Limits(
keepalive_expiry=...))` 로 간격보다 길게) — 을 **라운드마다 순서를 돌려가며** 친다.
순서를 안 돌리면 회선 변화가 그대로 '이 팔이 빠르다'로 둔갑한다(08-18 실측).
`max_retries=0` 은 필수다.

## 노트북(PC) 실측

    [1층] 소켓   DNS 0.000s · TCP 0.017s · TLS 0.019s (TLSv1.3)  ->  연결 여는 값 0.040s
    [2층] TTFT   cold 1.459s · reuse 1.482s · keepalive 1.583s   (42자 프롬프트, n=5)

- **연결 하나 여는 값이 0.040s 다.** keepalive 를 고쳐서 벌 수 있는 상한이 그것뿐이다.
- 팔 시험은 cold − keepalive = **−0.124s** 로 나왔다. 이득이 없다는 뜻이고, 애초에
  40ms 를 재려는데 실행 간 변동이 ±1.5s 라 분해가 불가능하다. 소켓 층이 상한을
  못 박으므로 팔 시험 없이도 결론은 선다.
- ➡️ **연결 재사용은 레버가 아니다. 고치지 말 것.**

## 더 중요한 것 — 바닥 1.5초의 97% 가 서버 쪽이다

42자 프롬프트인데 TTFT 중앙이 **1.5초**다. 그중 네트워크 핸드셰이크는 0.04초다.
그리고 이 값이 08-18 에 **젯슨**에서 잰 바닥 1.735s 와 거의 같다.

- 젯슨도 회선도 범인이 아니다. **OpenAI 서버 쪽 대기·프리필이 바닥을 만든다.**
- 08-21 의 "남은 길은 서버 이전(클로바)뿐"은 그 '왕복'을 **거리**로 읽은 처방이었다.
  거리는 40ms 뿐이다. 옮겨서 줄일 수 있는 건 거리가 아니라 그쪽 서버의 TTFT 이고,
  그건 09-01 에 **"gpt 와 구분 불가"** 로 이미 나왔다. 두 결과가 서로 맞는다.

⚠️ **젯슨에서 다시 잴 것.** 위는 노트북 값이다. 젯슨 소켓 층이 크게 나오면 이야기가
   달라진다(그때만 keepalive 가 다시 후보가 된다). 소켓 층만 재면 되고 키도 과금도
   필요 없으므로, 다시 볼 일이 생기면 **1층부터** 재라 — 40ms 가 상한을 못 박으면
   2층(팔 시험)은 안 쳐도 된다.

# 🟢🟢 2026-09-02 Realtime(S2S) 실측 — **반대 근거 두 개가 다 무너졌다**

`tools/realtime_probe.py`. "전부 API 로 가면 어떤가"에 우리 오디오로 답한 것이다.
벤더 수치는 전부 영어·성인이라 하나도 못 쓴다.

## 1) 지연 — 같은 꼬리 조건에서 −1.55초

어른 실음성 8클립(말끝을 프레임 RMS 로 정확히 자름), 노트북, `gpt-realtime-mini`.

| 조건 | 말끝→끝판단 | →첫 소리 | 합계 |
|---|---|---|---|
| VAD 500ms | 0.746s | 0.312s | **1.06s** |
| VAD **1200ms**(우리 꼬리와 동일) | 1.441s | 0.499s | **1.95s** |
| `gpt-realtime`(상위) VAD 500ms | 0.733s | 0.371s | 1.11s |
| **현행**(꼬리 1.20 + LLM 1.50 + TTS 0.78) | 1.20s | ≈2.3s | **≈3.5s** |

➡️ 꼬리를 똑같이 1.2초로 맞춘 조건에서 **1.95s vs 3.5s = −1.55초**. 이 프로젝트에서
   나온 어떤 이득보다 크다(TTS TensorRT −0.46s, 선행인식 −0.85s).

## 2) 아이 말 알아듣기 — **로컬 medium 을 이긴다**

AI-Hub 3~6세 40발화, 발화마다 새 세션(이력 누적 없음), VAD 1200ms.

| | 빈 전사 | CER 평균 | 완벽일치 |
|---|---|---|---|
| Realtime + `whisper-1` | **39%** | 62.9% | 4/39 |
| Realtime + **`gpt-4o-transcribe`** | **0%** | **36.9%** | 10/39 |
| 로컬 medium(같은 자·같은 발화) | — | 40.2% | 10/39 |

- 🔴 **전사 모델을 반드시 `gpt-4o-transcribe` 로 줄 것.** `whisper-1` 은 39% 확률로
  빈 문자열을 준다 — 안전 필터·claims·논문 로그가 먹을 재료가 사라진다.
- ➡️ `gpt-4o-transcribe` 면 **−3.36%p 로 우리 로컬보다 낫다.**
- 🔴 그리고 **모델의 이해는 전사보다 낫다.** whisper-1 팔에서 전사가 빈 15개 중
  7~9개는 답이 명백히 맞았다(`과자는 달콤해요`→"맞아, 과자 달콤하지!",
  `무릎이 아파요`→"어, 그럼 살살 마사지 해볼까?"). 텍스트를 안 거치므로 전사 오류가
  이해를 망치지 않는다. **"아이 말을 못 알아듣는다(CER 31%)"는 전제가 S2S 에선 다르게 논다.**
- ⚠️ 절대값은 README 위쪽 표(31.46%, 공백 포함)와 다르다. 여기 채점은 공백·문장부호를
  양쪽에서 지운다. **같은 자를 양쪽에 댔으므로 비교만 유효하다.**

## 3) 안전 — "사후"에서 "빠듯함"으로

출력 **전사 조각이 오디오 조각보다 먼저 온다** — 중앙 **+0.19초**(두 팔 모두).
소리를 그만큼 물고 텍스트로 먼저 검사하면 안전 순서를 지킬 수 있다.
⚠️ 다만 예산이 0.19초뿐이다. 넘으면 그만큼 지연이 는다. **불가능은 아니고 빠듯하다.**

## 4) 비용 — 세션을 짧게 끊으면 감당된다

턴당 $0.0017(mini). 오디오 ≈ **25토큰/초**(실측).
🔴 **입력이 턴마다 누적된다**(실측 턴1 19토큰 → 턴8 210토큰) — 대화 전체를 매 턴 다시
싣는다. 세션이 길면 비용이 제곱으로 는다.

| 세션 길이 × 하루 3세션 | mini | gpt-realtime |
|---|---|---|
| 10턴 | 월 5,400원 | 월 17,000원 |
| 20턴 | 월 19,000원 | 월 60,000원 |
| 40턴 | 월 71,000원 | 월 223,000원 |

(현행 월 4,100원.) 우리는 이미 `MAX_HISTORY_TURNS` 로 이력을 자르므로 그 규칙을 얹으면
10턴 줄에 가깝다. **안 자르면 답이 없다.**

## 아직 안 재 본 것

- **젯슨**. 위는 전부 노트북이다. 다만 같은 날 잰 API 왕복 분해에서 노트북 바닥(1.5s)이
  젯슨 바닥(1.735s)과 거의 같았다 — 크게 다르지 않을 가능성이 높다.
- 목소리(내장 음성만 됨. 블라인드로 고른 F2 를 잃는다), 폴백(끊기면 즉사),
  아동 원음 해외 전송, 벤더가 모델을 갈면 실험 재현 불가. 이건 실측 문제가 아니다.

## 5) function calling — **된다. 다만 낱말 규칙을 대체하진 못한다**

`tools/realtime_probe.py --tool-check` (글 입력, 3회 반복). 도구는
`configs/audio_assets.yaml` 에서 만든다 — 봇이 실제로 낼 수 있는 소리와 어긋나면
통과해도 옮길 수 있다는 뜻이 아니다.

🔴 먼저 사실 확인: **우리 봇은 지금 LLM function calling 을 안 쓴다.**
`agent.respond` 의 `function_call` 은 늘 None 이고, 소리는 `AudioLibrary.find` 의
낱말 규칙이 고른다. 그래서 물음은 "옮길 수 있나"가 아니라 **"모델이 규칙보다 나은가"** 다.

| 실행 | 낱말 규칙 | Realtime | 모델이 틀린 자리 |
|---|---|---|---|
| 1 | 12/14 | 12/14 | `강아지 소리 들려줘`(안 부름), `고양이 봤어`(헛호출) |
| 2 | 12/14 | 13/14 | `강아지 소리 들려줘`(안 부름) |
| 3 | 12/14 | 13/14 | `무슨 소리야`(헛호출) |

**기계적으로는 문제없다** — 올바른 도구 이름과 올바른 enum 값으로 부른다.

## 🔴 그런데 고장나는 방식이 다르다

- **모델이 항상 이기는 자리(3/3):** `왈왈 하는 소리 내봐` → dog, `야옹 해봐` → cat.
  별칭에 없는 **의역**이다. 낱말 규칙은 구조상 못 잡는다.
- **모델이 랜덤하게 헛호출한다:** `고양이 봤어` → cat(1/3), `무슨 소리야` → cat(1/3).
  🔴 **이건 커밋 `ad022ba`·`c3cf296` 에서 이미 고친 바로 그 오작동이다.** 도구 설명에
  "'고양이 봤어'는 요청이 아니다"라고 **명시했는데도** 한 번 불렀다.
- **약속하고 안 한다:** `강아지 소리 들려줘` 에 도구를 안 부르고 *"알겠어, 지금 들려줄게!"*
  라고만 했다(2/3). `audio_assets.yaml` 주석이 경계한 바로 그 고장이다
  ("봇이 '틀어줄게'라고 약속하지 않는다").
- 낱말 규칙은 **결정적이다** — 세 실행 내내 같은 자리(의역 2개)에서만 틀린다.

## ➡️ 읽는 법

점수는 사실상 동률(12 vs 12·13·13)이고, **모델이 버는 것(의역 2개)과 잃는 것(랜덤 헛호출)이
붙어 다닌다.** 규칙을 먼저 태우고 못 잡은 것만 모델에 넘겨도 헛호출은 그대로 새 들어온다
(규칙이 None 을 주는 자리가 곧 모델이 헛호출하는 자리다).

아이 대상에서 헛호출은 **원치 않는 소리가 갑자기 나가는 것**이라 더 나쁜 쪽 오류다.
➡️ **S2S 로 가더라도 소리 트리거는 낱말 규칙으로 남기는 게 맞다.** function calling 은
   '가능하다'로만 기록하고, 쓰려면 의역 보강용으로 **규칙이 승인한 뒤**에만 붙일 것.
